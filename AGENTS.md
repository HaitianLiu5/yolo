# AGENTS.md

Yolo is a private, agent-driven media service: a Cloudflare control plane (MCP, `/v1`, OAuth, the Hub), a media node on the owner's home machine, source plugins, and the player, one browser app served at the site root. In car mode the player decodes with Mediabunny and WebCodecs and draws frames to `<canvas>`, because Tesla can freeze a native `<video>` while the car moves; in web mode it plays through the browser's own `<video>`. All project knowledge — decisions, contracts, and proposals — lives in the [Agent Notes](.agents/notes/README.md); read the owning notes before proposing an architecture change, and follow [the documentation standard](.agents/notes/AGENTS.md#the-documentation-standard).

## Repository layout

```

clients/tizen/         the Samsung TV app (proposed, being built): a Tizen web app that opens the instance's player
service/core/          shared logic: sources, track preferences, capabilities, the agent canvas's objects, errors, HMAC signing, heartbeat, the ACME client

plugins/               official plugins: sources (source-plex, source-ytdlp, source-folder), the deSEC DNS provider (dns-desec), a fixed-URL proxy provider for the node's egress rules (proxy-url, not loaded by default), the Claude Code and Codex agents (agent-claude-code, agent-codex), a model for other plugins on the owner's own subscription (model-subscriptions), metadata from the owner's files, from Wikidata and Wikipedia, TVmaze, and Bangumi with no key, and from TMDB with the owner's optional key (metadata-local, metadata-wikimedia, metadata-tvmaze, metadata-bangumi, metadata-tmdb), AI subtitles over OpenAI's interfaces (subtitles-openai, not loaded by default), and source-example; official.json loads built-in link playback (source-ytdlp) and lists the catalog an owner turns plugins on from

test/conformance/      the client protocol's conformance kit, a scripted control plane a real client is proven against
```

## Code map

- `clients/player/src/main.js` owns pairing at startup, the realtime channel's messages, and routing; `store.js` keeps what the Hub sends every screen (its own session, every other screen's, its queue, the playlists), redraws the views that show it, decides whether previous and next have anywhere to go, reads what the Hub names next for the stream on screen, and picks the other screens' sessions to continue here; `mode.js` decides car or web mode; `realtime.js` is the realtime connection; `pairing.js` shows the QR code, approves a browser's own code with the owner's passkey, and polls the device grant; `api.js` holds the device credential and calls `/v1`; `owner.js` signs the owner in and calls `/v1/owner`; `tv-remote.js` moves focus with a TV remote's arrows and answers its Back on a screen paired as a TV, and `old-engine.js`, imported first, fills what engines as old as Chromium 85 lack, with `clients/player/old-engine-css.js` lowering the CSS for them at build time ([smart TV web client](.agents/notes/proposed/feature/2026-10-26-tv-web-client.md)).
- `clients/player/src/player.js` owns playback lifecycle and reports over either engine, answers at once a press that plays something else here (`beginStarting`), and keeps the player behind the home screen after Back, which `kept-player.js` decides when to release and how to go on; `player-screens.js` draws what stands in for the picture: the loading screen, a press's start, and the error panel, whose words `playback-error.js` chooses; `stream-recovery.js` keeps playback going with new streams from Yolo: recovery with a backoff until the new stream plays, Try again, and a new stream in place of one whose `load` a reconnect lost; `seek.js` seeks on this screen, in the stream or by a new stream from Yolo where the stream cannot seek, and watches until playback moves again; `telemetry/` keeps the player's runtime log (`player-log.js`), each stream's stalls, stutter reports, heartbeat, and decode health (`playback-telemetry.js`), what an engine's `getStats()` says (`engine-stats.js`), and slow media requests (`media-requests.js`); `video-freeze.js` says when the canvas engine's picture stopped while its sound plays on; `playback.js` and `stream-requests.js` ask Yolo for streams; `media-paths.js` probes the node's media origins and decides this screen's media path (LAN, remote, or the relay); `quality.js` is adaptive quality, which `quality-monitor.js` feeds every second and acts on; `unheard.js` keeps what the screen did that Yolo may not have heard (a stream left, the owner's pause, an end) for the welcome; `page-faults.js` reads the decoder faults in-car checks and tests open the page with; `display-scale.js` the display size; `resume-decision.js` what a returning page plays; `missed-commands.js` what a welcome says the screen never heard (commands a dead connection took); `growing-subtitles.js` re-reads AI subtitle tracks for a window around the position; `danmaku.js` draws timed comments over either engine's picture, laid out by `danmaku-layout.js`, with text measured and drawn in `danmaku-worker.js`.
- `clients/player/src/browse.js` owns the home screen, "Continue from another screen", search, episodes, queue, and history; `home-setup.js` asks a new home "Where do you usually watch?" and keeps "Add where you watch" at a skipped home's end; `plugins-settings.js` is Settings › Plugins; `track-menus.js` the player's subtitle and audio menus, and `tracks.js` loads the selected text subtitles of the stream on screen; `status.js` the one-line message over the home screen; `dom.js` the element builder and the controls more than one screen draws (a button that asks again, a switch, a choice of a few, dismissing a modal sheet, an item's card); `marquee.js` scrolls the player's title when it is too long; `share.js` plays a share link's one item at `/s/<token>` for a friend, unpaired and without the realtime channel; `settings.js` the settings sheet; `details.js` the player's sheet of what an item is (synopsis, cast, the upload it plays); `ask.js` the Ask panel that hands a request to the owner's agent, the one `agent-choice.js` says this screen chose; `canvas.js` draws what agents place on this screen (choices as a spotlight over home or a shelf over the picture, notes, pictures) and sends what the person does back; `remote.js` the now-playing bar, which controls one screen's session at a time, and its sheet of every session, with Continue here and Move to ([screen sessions](.agents/notes/implemented/architecture/2026-10-31-screen-sessions.md)); `up-next.js` the card that names what plays next in an item's last seconds, the end screen of what next would have played when an item stops at its end, and "Finished" when nothing follows; `play-target.js` where a tap plays; `picture-controls.js` fullscreen and AirPlay; `scroll-edges.js` marks a scrolling list's edges for their fades. `clients/player/src/engine/` holds the canvas engine (`mediabunny-player.js`: decoding, audio buffering, presentation timing, HLS prefetch; `decoder-recovery.js`: the steps a failed decoder climbs in place before a new stream), the `<video>` engine (`native-video-player.js`), and the engine choice (`native-support.js`).
- `clients/apple/YoloKit/` speaks the client protocol in Swift, apart from any UI: `Discovery.swift` checks `/.well-known/yolo` and `Bonjour.swift` finds `_yolo._tcp`; `Pairing.swift` runs the device grant; `Browse.swift` reads history, libraries, search, and episodes, chooses tracks, makes share links, and loads every picture from Yolo's origin; `Subtitles.swift` reads a stream's tracks, audio included, parses WebVTT, and reads growing tracks in windows; - `service/control/src/hub/hub-core.js` owns each screen's session (its state, commands, reports, progress, resume, and what plays next: its queue, then the run of what was playing), the default rule for a request that names no screen (`resolveScreen()`), the takeover (`transfer()`), and the agent canvas's actions; `canvas.js` keeps each screen's agent canvas, its event log, and agents' waits for it, while hub-core runs a pick's play or queue; `hub.js` wraps it in the Durable Object; `node-client.js` (`nodeFetch()`) is the only way to the node; `media.js` relays `/m/*` unless the owner turned the relay off; `edge/` keeps the node's LAN and remote names, DNS records, and certificates and the remote path's check from outside (the cron trigger, ACME DNS-01), through the DNS provider `edge/dns.js` chooses (Cloudflare's zone, built in, or a plugin's), one cron run at a time with at most one certificate order under a KV lease (`edge/maintain.js`, `edge/lease.js`), and `edge/paths.js` the media paths a welcome lists.
- `service/control/migrations/` holds the D1 schema; `src/plugins.js` runs plugins' control entries, bundled by `scripts/generate-plugins.js` into the ignored `src/plugins.generated.js`; `src/well-known.js` serves `/.well-known/yolo` and `/healthz` from `scripts/generate-build-info.js`'s ignored `src/build-info.generated.js`.
- `ops/yolo.js` dispatches `npm run yolo -- <command>` to `ops/commands/`; `commands/auth.js` signs in with `cf`'s device login (`lib/cf.js`) and makes wrangler's account API token (`lib/operator-token.js`), which `lib/credentials.js` passes to every wrangler; `ops/lib/instance.js` reads the instance file and `wrangler-config.js` renders the deploy config from the template; `media-dns.js` creates the DNS token with `cf` or sets up a DNS provider plugin through its setup entry (`setup-entry.js`), `commands/models.js` shows the plugins' model and signs Yolo in to a subscription, `commands/accounts.js` signs Yolo in to the video site accounts a source plugin plays with, `commands/plugins.js` lists the catalog and turns plugins on and off through the node's socket, `lib/plugin-config.js` keeps an upgraded instance's plugins, and `plan.js` reads the account's Workers plan and checks Workers Free's limits; `ops/wrangler.js` is `npm run wrangler`.
- `service/node/src/app.js` serves `/internal/v1/*` and `/m/*`; `edge.js` is the media listeners' HTTPS server that serves only `/m/*` and a probe, `lan.js` the one on the private LAN address, `wan.js` the one the internet reaches through a router port (with per-address limits), which without a domain certifies the home's public address itself (`acme-challenge.js` answers the CA), and `portmap/` maps that port by PCP, NAT-PMP, or UPnP IGD; ## Commands

```bash
npm install
npm run check                  # doc-sync, build, then unit, integration, and e2e tests
npm run doc-sync               # documentation gates (scripts/run-gates.js)
npm run build                  # clients/player/dist, then a dry-run Worker build that bundles it
npm run dev                    # Vite dev server for the player, proxying Yolo routes to YOLO_CONTROL_URL
npm run dev:control            # control plane via wrangler dev (needs service/control/.dev.vars, see .dev.vars.example)
npm run dev:node               # media node on 127.0.0.1:9191 (needs NODE_SECRET)
npm run owner-code             # 6-digit code from the running node for the first passkey or a reset
npm run yolo -- auth           # Cloudflare login from any device (cf's device flow), then wrangler's API token in .yolo/
npm run yolo -- doctor         # one instance's status, every check with its fix (--json; --offline)
npm run yolo -- tools status   # the yt-dlp and Deno builds tools.json pins (install; bump <tool> pins its latest release)
npm run yolo -- plugins list   # the plugins the node can offer; on|off <plugin|place> applies in place
npm run yolo -- help           # the other operator commands: init, provision, migrate, deploy, service, upgrade, rollback, image-links, models, accounts
npm run wrangler -- <args>     # wrangler in service/control with the instance's rendered config
npm run verify-translation-pairing -- --write <pair>   # re-record a confirmed bilingual pair
node scripts/render-readme-diagram.js                  # re-render the README's diagram PNGs from .github/readme/architecture.html
node scripts/render-icons.js                           # re-render every client's icons and favicons from the line in service/core/src/brand.js
swift test --package-path clients/apple/YoloKit        # the Apple clients' protocol tests (macOS only)
npm run test:conformance       # the conformance kit against the client YOLO_CONFORMANCE_LAUNCH starts ({url} is the kit); skipped without it
xcodebuild -project clients/apple/Yolo.xcodeproj -scheme YoloTV -destination 'generic/platform=tvOS Simulator' build
clients/apple/archive.sh                               # a Release archive of the Apple TV app, uploaded for TestFlight (--no-upload to only archive)
```

Node.js 22.12 or newer is required. The node needs `ffmpeg`; `npm install` downloads the yt-dlp and Deno builds `tools.json` pins into a shared cache and links them in `.tools/bin`, which the node puts first on its PATH (`YOLO_TOOLS=skip` skips it) ([pinned tools](.agents/notes/implemented/process/2026-10-25-pinned-node-tools.md)); the e2e tests need ffmpeg and Chromium (or Google Chrome), and `YOLO_E2E_WEBKIT=1` adds Playwright's WebKit. The Apple clients need macOS with Xcode and the tvOS platform; `npm run check` does not build them.

## Rules

- Use plain JavaScript ES modules and 2-space indentation. Do not add TypeScript or a transpiler. The yt-dlp plugin's `yt-dlp/` directory holds yt-dlp extensions in Python, which only yt-dlp loads ([Tencent Sports replays](.agents/notes/implemented/feature/2026-10-26-tencent-sports-replays.md)). The one other exception is `clients/apple/`, the native Apple TV app, in Swift with SwiftUI and AVPlayer, since tvOS has no web engine; it also uses 2-space indentation, carries no content or provider names, and keeps the owner's team id and bundle id prefix in the ignored `clients/apple/Local.xcconfig` ([Apple TV client](.agents/notes/proposed/feature/2026-10-19-apple-tv-client.md)).
- A Tesla plays with the canvas engine: car mode, and any page the Tesla fingerprint recognizes, whatever device type the owner chose; `<video>` breaks the core Tesla use case. Keep decoded video queues bounded, buffer network jitter as encoded segments, and keep HLS prefetch single-flight ([canvas engine](.agents/notes/implemented/architecture/2026-04-04-canvas-playback-engine.md)).
- Web mode plays through the browser's `<video>` element; both engines stay behind `player.js`'s one engine interface and keep the position on quality or viewport changes, and `engine/native-support.js` chooses from the mode and the Tesla fingerprint ([two engines](.agents/notes/implemented/architecture/2026-10-12-two-playback-engines.md)).
- COOP/COEP are required for the canvas engine's SharedArrayBuffer audio clock and stay on every page, since a page learns its mode only after it loads; keep the client same-origin with `/m/*` and `/v1/realtime`, and list Yolo's own routes in `wrangler.jsonc` `assets.run_worker_first` ([same-origin passthrough](.agents/notes/implemented/architecture/2026-10-07-same-origin-media-passthrough.md)). The exceptions are the node's media origins, LAN and remote, which answer only `/m/*` and the probe with CORS and CORP for the page; every media URL of a stream resolves against the stream's `origin` ([LAN direct play](.agents/notes/implemented/feature/2026-10-12-lan-direct-play.md)).
- `/m/*` URLs are authorized only by the media token in the path; device credentials are checked against D1 on every request ([device code pairing](.agents/notes/implemented/feature/2026-10-07-device-code-pairing.md)).
- Media goes from the node to the device by the first direct path that works, LAN direct play then remote direct play; the Worker's `/m/*` relay is the fallback, used for a screen only when no direct path works for it (`auto`, the default) and never when the owner set it `off`. Keep direct paths first, keep the relay last, and never reshape its responses ([media off the Worker](.agents/notes/implemented/architecture/2026-10-13-media-off-the-worker.md)).
- Core, control, and node code must not know specific providers: no tracked file under `service/` may name one, except the D1 migrations and the migration test that convert 0.1 rows; `scripts/provider-names.test.js` enforces this in `npm run check`, with the names it takes from `plugins/`. Plugins import only `@useyolo/plugin-api` from Yolo, and an official one follows the [`yolo-add-official-plugin`](.agents/skills/yolo-add-official-plugin/SKILL.md) workflow ([plugin architecture](.agents/notes/implemented/architecture/2026-10-11-plugin-architecture.md)).
- A source plays by returning an Input from `prepare()`; it never serves HTTP or caches segments itself ([media pipeline](.agents/notes/implemented/architecture/2026-10-11-node-media-pipeline.md)).
- The control plane reaches the node only through `nodeFetch()` ([node access](.agents/notes/implemented/architecture/2026-10-08-workers-vpc-node-access.md)).
- Every D1 table has `user_id`; never edit an applied migration, add the next number, and write it to work with the previous release's code ([D1 data model](.agents/notes/implemented/architecture/2026-10-07-d1-data-model.md)).
- Yolo has one version, the root `package.json`'s, on every package; a change to `/internal/v1` that the previous release's other side cannot follow raises `NODE_PROTOCOL`, and one to `/v1` or the realtime channel that the previous release's clients cannot follow raises `CLIENT_PROTOCOL` ([client protocol](.agents/notes/implemented/architecture/2026-10-19-client-protocol.md)); every release has a `CHANGELOG.md` entry with its `yolo-upgrade` block ([versions and releases](.agents/notes/implemented/process/2026-10-13-versions-and-releases.md)).
- The realtime client sends `HEARTBEAT_PING` exactly, never answers broadcasts, and backs off at least 30 seconds after rate limits ([Hub and realtime channel](.agents/notes/implemented/architecture/2026-10-07-hub-and-realtime-channel.md)).
- Text subtitles are rendered in the browser; image subtitles are burned in by the source ([capability negotiation](.agents/notes/implemented/architecture/2026-10-07-capability-negotiation.md)).
- Playback starts with sound when the browser allows it; otherwise it plays muted with a "Tap for sound" prompt until the first tap ([progress and resume](.agents/notes/implemented/feature/2026-10-11-yolo-owns-progress-and-resume.md)).
- The privacy policy at `site/public/privacy.html` and `site/public/zh/privacy.html` is the App Store's for every client: a change that makes a client send, or the server keep, something new updates both pages in the same change ([useyolo.app website](.agents/notes/implemented/process/2026-10-23-useyolo-app-website.md)).
- Modules under `service/control/src` that tests import must not import `cloudflare:workers` (only `index.js` and `hub/hub.js` may) ([test layers](.agents/notes/implemented/testing/2026-07-21-test-layers.md)).
- Configuration belongs in environment variables documented by `.env.example`; which plugins load, in what order and with which options, belongs in `yolo.config.json`; an instance's address (its domain, or its workers.dev host without one) and Cloudflare ids belong in the ignored `yolo.instance.json`, never in `service/control/wrangler.jsonc`, which stays a template ([agent deployment](.agents/notes/implemented/feature/2026-10-13-agent-deployment.md)). Runtime state belongs in ignored paths (`.yolo/` with deployment records, D1 backups, the tunnel token, and the Cloudflare API token, `.yolo-node.sock`, `.lan/` with the node's LAN and remote keys and certificates, `.hls-cache/`, `.media-cache/`, `.segment-cache/`, and `.logs/`). Never commit tokens, databases, logs, caches, `yolo.config.json`, `yolo.instance.json`, `service/control/wrangler.instance.jsonc`, or `clients/player/dist/`.
- To sign in to Cloudflare, run `npm run yolo -- auth`, which uses `cf`'s device flow, not `wrangler login`, whose localhost callback needs the browser on this machine. Always give the owner the verify link with the code filled in, `https://dash.cloudflare.com/oauth2/device/verify?user_code=<code>`, and the code beside it: it works from a phone ([signing in to Cloudflare](.agents/notes/implemented/feature/2026-10-13-agent-deployment.md#signing-in-to-cloudflare)).
- Never run tests or a second node against the live node's runtime directory or port 9191.
- Name branches `<kind>/<topic>` and write commit messages as [CONTRIBUTING.md](CONTRIBUTING.md#branches-and-commits) describes.

## Agent Notes and documentation

- All project knowledge lives in Agent Notes; there is no `docs/` folder, and the classification gate rejects one ([rationale](.agents/notes/implemented/process/2026-10-12-agent-notes-hold-project-knowledge.md)). The root README, CONTRIBUTING, SECURITY, CODE_OF_CONDUCT, and CHANGELOG files are GitHub's entry points, not a second home for knowledge. Deploying, upgrading, or diagnosing an instance follows the skills in `skills/` (`yolo-deploy`, `yolo-upgrade`).
- **Create Agent Notes only for durable decision rationale;** mechanical/local edits are exempt, including local UI changes ([scope](.agents/notes/README.md#when-to-write-one)). Archived notes are frozen: never edit or treat them as current authority ([archive policy](.agents/notes/README.md#archiving-and-deletion)).
- Docs accompany every code change: update the implemented note that owns a changed path, default, or contract in the same change. Documents link notes by path; code comments cite `Agent Note <file stem>`; never cite a decision or section number.
- Bilingual pairs update together: change both languages, then re-record with `npm run verify-translation-pairing -- --write <pair>` ([contract](.agents/notes/implemented/process/2026-10-12-bilingual-documentation.md)).

## Verification

Run `npm run check` for every change. The e2e tests run the stack (node, `wrangler dev --local`, Chromium) on free ports with local D1 and KV; they never touch Cloudflare or a running node. For route or playback changes, also check the affected stream type in the car: `hls`, `direct`, `dash_split`, or `plex` ([in-car checks](.agents/notes/implemented/testing/2026-07-21-test-layers.md#in-car-checks)). For `<video>`-engine changes, also run the e2e tests with `YOLO_E2E_WEBKIT=1` or check in Safari.

## Cloud sessions

Cloud agent sessions block `api.cloudflare.com` and `dash.cloudflare.com`, so `wrangler` and `cf` (Cloudflare's official CLI, npm package `cf`, reinstalled after every container rebuild) cannot reach Cloudflare there unless the environment's network access allows those domains. The Cloudflare connector for claude.ai is not affected and can call the Cloudflare API directly.
