# Agent Note: 2026-09-05 Drive-In 仓库评审后的修复

Status: implemented
Archived: 2026-10-12

[English](2026-09-06-drive-in-review-fixes.md) | 中文

## 问题

2026-09-05，在 Yolo 出现之前，对 Drive-In 仓库的一次评审发现了横跨旧服务、播放器和部署的缺陷：缓存冲突、短流结尾处播放卡住、字幕重新出现或导致播放失败、恢复循环，以及被悄悄忽略或强加给所有人的配置。

## 决策

每个发现都附带回归测试修复了；另行要求的删除 Docker 支持也保留下来。

| 发现 | 处理 |
|---|---|
| HLS 缓存冲突 | 通用分片的缓存键包含完整 URL 和确切的字节范围；旧的只按路径的键不再复用。各服务商的签名 URL 标识仍然支持 |
| 短 HLS 一直缓冲 | 带 ENDLIST 的播放列表会说明剩下的每个分片（包括当前分片）是否都已缓存；只有完全可用的有限结尾才绕过前向缓冲目标，而且仍然需要解码 |
| 远程 Plex 的内嵌字幕导致播放失败 | 缺失或无法访问的源路径得到烧录描述，不再为它们安排本地抽取 |
| 音频比视频短时播放冻结 | worklet 会排空最后一个不完整的音频块；音频结束并排空后，时钟从同一位置改用墙上时钟继续，跳转后恢复音频时钟 |
| 旧的停止操作停掉了新的播放 | 停止在等待异步清理之前，就随同步的停止意图广播出去 |
| 替换播放器时丢失静音状态 | 每个新播放器都应用当前的静音状态，与音频上下文是否解锁无关 |
| 暂停状态下的恢复循环 | 新的暂停中的播放器无需播放进度就能确认就绪，旧播放器也不能替新播放器确认 |
| 迟到的字幕重新出现 | 音轨加载可以取消，并检查当前请求；关闭、移除、替换和新的播放都会让旧的加载失效 |
| Plex 偏移量为零时被忽略 | 显式的零被保留；非数字、负数和非有限值的偏移被拒绝；省略偏移时仍按 Plex 的进度续播 |
| 缺少转码初始化 URI | 共用的 HLS 改写同时处理 URI 属性（EXT-X-MAP）和媒体行 |
| URL 的 SRT 转换未定义 | 下载器成为可测试的模块，并导入现有的 SRT 转换器 |
| 强制使用 Chrome cookie | cookie 改为可选，通过 yt-dlp 的浏览器或文件选项显式配置 |
| 本地 `.env` 被忽略 | Node 原生的 env 文件加载在日志和存储启动之前运行；已导出的环境变量优先 |
| Docker 部署问题 | Dockerfile、Compose 文件、Docker CI 及其更新配置应用户本人要求删除 |

同一项工作还修复了跳转时转圈的竞态，让只有一个分片的 ffmpeg 输出也能就绪，并让分离流的自我探测使用实际绑定的端口。在现有版本范围内更新 lockfile 后，`npm audit` 报告零个安全公告。最终的 `npm run check` 运行了 178 个测试和生产构建。

## 曾考虑的替代方案

**引入新的运行时库。** 没有加任何运行时库：修复扩展了现有的缓冲策略、共享音频环形缓冲、播放生命周期和字幕转换器；HLS URI 处理由通用代理和 ffmpeg 输出共用，而没有引入另一个播放器或清单依赖。

## 后果

部署之前，根目录的 `.env` 开始在启动时生效（已导出的值仍然优先）；依赖 Chrome 登录的安装必须设置 `YTDLP_COOKIES_FROM_BROWSER=chrome` 或 `YTDLP_COOKIES_FILE`；旧缓存键下的通用 `.ts` 条目不再命中，随正常淘汰过期；服务和重新构建的播放器必须一起部署，让 worklet 的音频结束标志和播放器时钟保持一致。特斯拉硬件、行驶中的车载网络，以及真实的 YouTube、Bilibili 和 Plex 账号，仍需要在车上验收。
