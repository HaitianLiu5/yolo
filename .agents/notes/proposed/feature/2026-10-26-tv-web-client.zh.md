# Agent Note: 在智能电视自带的网页引擎上运行播放器

Status: proposed

[English](2026-10-26-tv-web-client.md) | 中文

## Problem

运行三星 Tizen 或 LG webOS 的智能电视有网页引擎，却没有 Yolo 客户端。[原生 Apple TV 应用](2026-10-19-apple-tv-client.zh.md)之所以存在，是因为 tvOS 没有网页引擎；这些电视有，所以播放器本身就能在上面运行。挡在中间的有三件事，都是在一台三星 QN90B（2022 款，Tizen 6.5）上发现的。

- **没有入口。** 电视上没有让主人输入 Yolo 地址的浏览器地址栏，需要一个已安装的应用来打开它。
- **没有指针。** 遥控器只有方向键、OK、返回键和媒体键。播放器是为触屏和鼠标做的：没有焦点移动，主页上什么都选不到，返回键也不起作用。
- **引擎太旧。** Tizen 6.5 的引擎是 Chromium 85。播放器的 CSS 用了 `oklch()` 颜色（Chrome 111）、容器单位（105）、`:has()`（105）、`inset`（87）和 `aspect-ratio`（88），JavaScript 用了 `replaceChildren`（86）、`Array.prototype.at`（92）和 `structuredClone`（98）。在这个引擎上页面是白底，配对页排版散乱，卡片封面高度为零。绝对定位的 `<button>` 在那里也不会在 `left` 和 `right` 之间拉伸。

播放不是障碍：在网页模式下，`<video>` 加上走 Media Source Extensions 的 hls.js 通过局域网直连播放 1080p H.264 流，零丢帧，有声音和文字字幕（[两个引擎](../../implemented/architecture/2026-10-12-two-playback-engines.zh.md)、[局域网直连播放](../../implemented/feature/2026-10-12-lan-direct-play.zh.md)）。

## Proposal

电视运行的就是 Yolo 在站点根路径提供的同一个播放器，由一个小的已安装应用打开，并在三处做适配。

**Tizen 应用。** `clients/tizen/` 存放一个 Tizen 网页应用（`config.xml`、一个页面和 `main.js`），它注册遥控器的媒体键（只有已安装应用自己的页面能注册），然后把自己替换成实例的播放器。实例地址不进仓库：`node clients/tizen/build.js --origin https://<instance>` 把它写进 `origin.js`，并用 Tizen CLI 当前启用的签名配置签出 `dist/Yolo.wgt`。开发者模式下，用自签名的 Tizen 作者证书就能安装，不需要三星账号。电视上显示的其余一切都来自实例，所以每次部署 Worker 时，电视和其他屏幕一起更新。

**以电视身份配对。** `guessDevice` 先于浏览器名和系统名识别智能电视的引擎，因为这些引擎的 user agent 里也带着它们（Tizen 的 user agent 写着 Safari 和 Linux）：Tizen 配对为「Samsung TV」，webOS 配对为「LG TV」，两者都是 `kind: "tv"`。

**遥控器**（`clients/player/src/tv-remote.js`），在配对为电视的屏幕上，或在配对前的电视引擎里生效：

- 方向键把焦点移到最上层里该方向上最近的控件：打开的对话框、主页，或者播放器控制栏（显示时）。左右键留在本行内，到行尾就停；上下键选下方或上方最近的控件，横向偏移按两倍距离计算。只供鼠标使用的行滚动箭头会被跳过，焦点沿一行移动时这一行随之滚动。
- 焦点进入一个页面时，回到它上次在这个页面的位置，否则落到第一张卡片。
- OK 键像浏览器一样按下当前焦点的控件，也能选中单选项；在一组单选项上，左右键切换到下一个选项。
- 返回键依次：关掉最上层的对话框，收起播放器控制栏，从播放器回到主页，离开剧集页；在文本框里则离开文本框。
- 控制栏隐藏、停在画面上时，左右键像电脑方向键一样快进快退（`controls.js`），上下键和 OK 键调出控制栏并把焦点放在播放按钮上。
- 媒体键负责播放、暂停、快进快退、切换上下一个和停止。Tizen 的返回键和媒体键按键码识别，因为它的按键名不固定。

**旧引擎。** 播放器的构建支持旧到 Chromium 85 的引擎，且不改变新浏览器的显示效果。`vite.config.js` 把 `chrome85` 加进构建目标，于是 Vite 降级 JavaScript 语法，并通过 lightningcss 降级嵌套、`:is()` 和逻辑盒属性。`clients/player/old-engine-css.js` 是一个 PostCSS 插件，处理剩下的部分：sRGB 色域内的 `oklch()` 颜色变成等值的 `rgb()`（播放器的 54 种颜色都在色域内）；`inset` 展开成四个方向；含容器单位的值在 `@supports not (width: 1cqw)` 里得到一份视口单位的副本（容器 #app 铺满窗口，除非主人选了显示大小）；`:focus-visible` 规则在 `@supports not selector(:focus-visible)` 里得到一份 `:focus` 副本；`aspect-ratio` 旁边加上 `--yolo-aspect-ratio`。`src/old-engine.js` 由 `main.js` 最先导入，只在引擎缺少时补上缺失的方法（`replaceChildren`、`at`、`findLast`、`Object.hasOwn`、`structuredClone`、`AbortSignal.timeout` 和 `any`）；在不支持 `aspect-ratio` 的引擎上，它按宽度和计算样式里的比例，给每个匹配带 `--yolo-aspect-ratio` 规则的元素设置高度。`:has()` 无法降级；用到它的几条规则（获得焦点时保持控制栏显示、卡片的悬停按钮）在这种引擎上不起作用。卡片上覆盖整张卡片的按钮除了 `inset: 0` 之外还写明宽高，因为 Chromium 85 不会按 `inset` 拉伸 `<button>`。每一项都已在 QN90B 上通过调试器注入的兼容层验证过；整个构建还没有在电视上加载过。

### Stages

1. Tizen 应用、以电视身份配对、遥控器。已完成：在 QN90B 上通过调试器，用方向键、OK 键和返回键可以在主页、剧集页、设置和播放器控制栏之间操作。
2. 把兼容层放进播放器的构建，让从电视主页打开应用也能正常使用。已完成构建，尚未在电视上加载。
3. 适合客厅观看距离的更醒目的焦点框；4K 流（引擎报告的视口是 1920×1080，所以目前 `maxHeight` 是 1080）；LG webOS 应用。

## Alternatives considered

**基于三星 AVPlay 的原生 Tizen 应用。** 它会用电视自己的播放器，能达到 4K 和 HDR，但要针对一家厂商的接口重写客户端协议、浏览、字幕和弹幕，就像 Apple TV 应用因为 tvOS 没有网页引擎而必须做的那样。这些电视有网页引擎，所以播放器可以原样运行，并随每次部署获得之后的所有功能。

**把构建好的播放器打包进 `.wgt`。** 页面可以离线加载，也能自带 polyfill，但它的源会是应用的而不是 Yolo 的，于是 `/m/*` 和实时通道的同源规则、存储里的设备凭证、COOP/COEP 都需要例外，而且每次 Yolo 发布都要在电视上重新安装。打开实例自己的页面，就只有一个播放器、一个源。

**在电视 HDMI 口上接一个安卓电视盒子。** 它运行的是新版 Chromium 或原生应用，完全不需要这些兼容工作，但主人得另外买硬件，而电视自己的系统仍然没有 Yolo。原生安卓电视应用之后也许会出于它自己的理由再做。

**只靠 Vite 的 CSS 构建目标。** 把 `chrome85` 加进目标后，lightningcss 降级了大部分颜色和选择器，但留下了容器单位、`:focus-visible`、`aspect-ratio`、含 `var()` 或 `calc()` 的 `inset`，还有两个长写法属性里的 `oklch()` 颜色没有降级；这些都曾让电视上的页面出错。插件补的正是这几项。

**用 `@supports` 保留 `oklch()`，另给 `rgb()` 回退。** 这样新浏览器能保留广色域颜色，但播放器用到的颜色全在 sRGB 色域内，那里的 `rgb()` 就是同一个颜色，所以构建直接写成 `rgb()`，色域外的颜色保持原样。

**引擎自带的空间导航。** Chromium 内置的空间导航是浏览器设置，不是页面能打开的，而且它不知道播放器的分层：它会把焦点移进主页背后隐藏的控制栏，而这个引擎无法把它们标为 `inert`（Chrome 102）。

## Acceptance criteria

- 从电视主页打开 Yolo，播放器显示深色主题、海报比例正确，可以通过二维码或配对码以电视身份配对，并通过局域网直连播放。
- 主页、剧集页、设置和播放器的每个界面都能只用遥控器到达和操作，返回键总是朝主页方向退。
- 新浏览器的显示与加兼容层之前完全一致，`npm run check` 通过。

## Risks

- **兼容层是第二条渲染路径。** 播放器每采用一个新的 CSS 特性或 JavaScript 方法，都可能让电视再次出问题。用一项构建检查列出比最旧支持引擎更新的特性就能发现它们；没有这项检查，问题只会在电视上暴露。
- **开发者模式安装。** 安装需要电视的开发者模式填写这台 Mac 的地址并重启电视，还需要 Tizen CLI。发布到三星商店可以免去这些，代价是三星的审核和证书。
- **媒体键可能到不了页面。** 只有已安装应用自己的页面能注册媒体键；它把窗口交给实例页面后注册是否还有效，尚未验证。
- **1080p。** 引擎在 4K 面板上报告 1920×1080 的视口，所以播放器请求 1080p；要播 4K，需要电视自己的播放器，或者能读到面板真实尺寸的办法。
