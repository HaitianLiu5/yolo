# Agent Note: Yolo 1.0 and the path to it

Status: proposed

English | [中文](2026-10-11-yolo-1-0.zh.md)

## Problem

Yolo 0.4.0 works for one owner, and another owner's agent can deploy it for them. A Cloudflare control plane and a media node on a Mac serve one player, which plays in the car with the canvas engine and in any other browser, iPhone included, with the `<video>` engine ([two engines](../../implemented/architecture/2026-10-12-two-playback-engines.md)); media comes straight from the node at home ([LAN direct play](../../implemented/feature/2026-10-12-lan-direct-play.md)); Plex and web video are plugins; Yolo keeps one history with resume, a queue, and playlists across devices ([progress and resume](../../implemented/feature/2026-10-11-yolo-owns-progress-and-resume.md)); agents drive it over MCP ([remote MCP server](../../implemented/feature/2026-10-07-remote-mcp-server.md)); and an agent deploys, upgrades, and rolls back an instance from tagged releases ([agent deployment](../../implemented/feature/2026-10-13-agent-deployment.md), [versions and releases](../../implemented/process/2026-10-13-versions-and-releases.md)).

As of 2026-10-13, four gaps keep Yolo from being recommended to anyone else:

- **Media away from home passes through the Worker.** Cloudflare's terms most likely restrict serving video hosted outside Cloudflare on a proxied hostname, and each owner would carry that risk on their own account ([media off the Worker](../architecture/2026-10-13-media-off-the-worker.md)).
- **Sources need Plex or yt-dlp.** Only the yt-dlp plugin claims URLs, so a direct `.mp4` or `.m3u8` link still needs it and a DASH manifest has no path; the node reads no local file, so without Plex the files on a NAS do not play.
- **Security blockers.** An open redirect after passkey sign-in, media tokens and pairing codes in Workers Logs, and a canvas engine that retries a failing segment forever.
- **The repository carries its history.** CI fails on Node 22, the retired Drive-In name appears in current documents and settings, and several notes contradict the code.

Without a definition of 1.0 that closes these, the next versions have no shared target, and work that can wait (recommendations, TV and phone apps, multi-user households) competes with work that cannot.

## Proposal

### What Yolo is

Yolo is an **entertainment canvas for the agent era**:

- **Agents drive it.** ChatGPT, Claude, and Codex search, play, and control playback for the user over MCP.
- **One player frees the user from each platform's limits.** It covers the car with the canvas engine and the web with the `<video>` engine; TV and phone come later.
- **No source is required.** Plex and yt-dlp are plugins like any other; Vimeo, a direct link on any CDN, and files on a NAS play through source plugins.
- **It keeps the user's state, as Plex does:** history, resume, a queue, and playlists, shared by every device.
- **It is built from plugins.** Sources, protocol servers (a Jellyfin-compatible API for Infuse and Apple TV), proxies, and recommendation feeds can all be community plugins.
- **Its D1 model is healthy and extensible:** every row keyed by user, nothing tied to one source, and room for a catalog and new kinds of items.
- **Later, recommendations run on the user's own subscription.** Yolo holds the state (follows, an inbox) and exposes MCP tools; the user's own ChatGPT or Codex agent does the thinking on a schedule.

### Decisions

- **Media leaves the Worker for 1.0.** Cloudflare's CDN terms say that "unless you are an Enterprise customer, Cloudflare offers specific Paid Services (e.g., the Developer Platform, Images, and Stream) that you must use in order to serve video and other large files via the CDN" ([Service-Specific Terms, Application Services](https://www.cloudflare.com/service-specific-terms-application-services/), updated 2026-09-28). Cloudflare's explanation adds that "video and large files hosted outside of Cloudflare will still be restricted on our CDN" ([blog, 2023-05-16](https://blog.cloudflare.com/updated-tos/)), and its documentation applies the restriction to public hostnames and exempts only private network routes ([delivering videos](https://developers.cloudflare.com/fundamentals/reference/policies-compliances/delivering-videos-with-cloudflare/)). Yolo's video is hosted on the owner's node and served on the Worker's public hostname. The Worker therefore keeps control only, and media takes the first path that works: LAN direct play, remote direct play through a router port forward to a DNS-only name with a real certificate (covering the car on LTE), then Tailscale for phones and computers. The relay stays, off by default and behind a plain warning; R2 staging, the compliant all-Cloudflare path, is deferred; the owner may also ask Cloudflare support for a written answer. The design is [media off the Worker](../architecture/2026-10-13-media-off-the-worker.md).
- **The public identity is HaitianLiu5:** the repository, the copyright holder, the package author, and the code owner.
- **One version for every package, starting at 0.4.0,** released as a `vX.Y.Z` git tag with an entry in [`CHANGELOG.md`](../../../../CHANGELOG.md) ([versions and releases](../../implemented/process/2026-10-13-versions-and-releases.md)). Every version below is such a release.
- **The Drive-In name is retired.** The car is the player's car profile, and "Tesla" names only the vehicle and its browser.

### Versions

Every version is a tagged release that is usable on its own: if the next one never ships, the system is still complete. Each item is rated low, medium, or high complexity with its main difficulty, never with time.

#### Friends preview

The friends preview is the first tagged release at which the owner can let a friend try Yolo. It needs the 0.4 line and one item of 0.5, and nothing else:

1. The friend creates and owns their Cloudflare account and domain; the owner never signs up for them, which Cloudflare's agreement forbids (§2.2.1(a)).
2. The friend's agent deploys from a fresh clone at the release tag with [`yolo-deploy`](../../../../skills/yolo-deploy/SKILL.md), stopping only at its checkpoints, `yolo doctor` passes, and the agent later upgrades the instance with [`yolo-upgrade`](../../../../skills/yolo-upgrade/SKILL.md).
3. The security blockers are fixed and unauthenticated routes are rate-limited, because the friend's instance is public from its first deploy.
4. The relay is off on a new instance, and turning it on shows the plain warning: the low-complexity relay switch of 0.5, brought forward. At home the friend plays by LAN direct play; away from home, until 0.5 ships, only through the relay and only by the friend's own choice.
5. CI is green, and nothing a friend reads or runs carries the owner's domain, resource ids, or the Drive-In name.
6. The friend's sources are Plex or yt-dlp, as in 0.4; the README states the preview's limits and asks for reports through GitHub issues.

## Alternatives considered

**Keeping the Worker relay as the default media path.** It needs no setup, but it is most likely outside Cloudflare's terms on Free, Pro, and Business zones and clearly outside them on Workers Free, and each friend would carry that risk on their own account ([media off the Worker](../architecture/2026-10-13-media-off-the-worker.md)).

**The Jellyfin protocol plugin in 1.0.** It is the cheapest way to Apple TV and iPhone players, but 1.0 covers the car and the web. The plugin needs host features that no 1.0 criterion needs (control-plane routes, plugin storage, a device interface in the Hub), and its premise, Swiftfin's remote control, is still unverified. Those features add to the plugin API without breaking it, so they can follow 1.0.

**The own library before independence from yt-dlp.** The node cannot read a local file or remux one, so the folder and WebDAV sources build on the local-file Input and remux of 0.6, and the direct-URL source makes yt-dlp optional at low cost.

**Installers and a setup wizard before agent deployment.** Agents deploy Yolo, so idempotent commands with stopping points come first; a wizard and installers wrap the same commands in 0.9.

**Native apps for 1.0.** They would have to pass App Review (guidelines 2.1 and 5.2.3) and be maintained every year; TV and phone come after 1.0, first through the Jellyfin protocol ([Jellyfin proposal](2026-10-11-jellyfin-protocol-plugin.md)).

**Emulating a Plex server for third-party clients.** [Rejected](../../rejected/architecture/2026-10-11-emulate-a-plex-media-server.md): plex.tv's claim mechanism and Plex's terms do not allow it.

## Acceptance criteria

1. **A friend's agent deploys and upgrades it.** In a fresh clone at the 1.0 tag, an agent working for a new owner deploys onto that owner's Cloudflare account and domain with the shipped skills, `yolo doctor`, and the ignored instance file, stopping only at the checkpoints the skills list; later it upgrades to the next release and rolls back, after showing the changelog's upgrade block for approval. No tracked file holds an instance's values.
2. **Media does not depend on the Worker relay.** On a new instance the relay is off; the car on LTE plays the four stream types (`hls`, `direct`, `dash_split`, `plex`) by remote direct play; a phone away from home plays through Tailscale; and the acceptance criteria of [media off the Worker](../architecture/2026-10-13-media-off-the-worker.md) hold.
3. **yt-dlp is optional.** With the yt-dlp plugin absent and no yt-dlp binary installed, direct `.mp4`, `.m3u8`, and `.mpd` links on an arbitrary CDN play in both profiles with a title and a duration.
4. **Local and NAS files play.** An owner without Plex plays films and series from a local folder and from a NAS share, with posters and synopses, in both profiles, including a file that needs a remux and one that needs a transcode, with seeking, resume, and history.
5. **The security blockers are fixed,** each with a regression test; unauthenticated routes are rate-limited; and the internet-facing surfaces, the Worker's routes and the node's remote listener, have a recorded security review.
6. **The repository is clean.** CI is green on every Node version the packages support; every package carries the release's version; the Drive-In name appears only in archived notes and one origin line; no tracked file carries an owner's domain or resource ids; the one-release name fallbacks are gone; and the contributor guide takes a newcomer to a playing browser.
7. **The rest of the 1.0 table holds** for a new owner who follows the published instructions: resume and watched state survive any history length and follow an item across sources, MCP covers the queue, playlists, history, and settings, and `@useyolo/plugin-api` 1.0 is published with documentation, an example plugin, and a conformance kit.

## Risks

| # | Assumption | If it fails | Who checks, when |
|---|---|---|---|
| 1 | Most owners can forward a port to the node | Behind carrier-grade NAT or without router access, phones and computers use Tailscale and the car has only the relay at the owner's choice; R2 staging moves ahead of the other 1.x work | The `edge` telemetry of the first friends' instances, in 0.5 |
| 2 | The car's browser on LTE reaches the home's address on the forwarded port | Forward external port 443, or rely on IPv6 where the car's network has it | The owner, in the car on LTE, during 0.5 |
| 3 | Self-hosted software may ship a TMDB API key | Each owner registers a key, one more setup step | Before 0.7 |
| 4 | A plugin API frozen from source and metadata plugins holds for protocol, device, feed, and proxy plugins | Their interfaces arrive as additive minor versions; a breaking need waits for 2.0 | When the Jellyfin plugin starts |
| 5 | Swiftfin on tvOS executes remote commands reliably | A native tvOS app that speaks the same Jellyfin session protocol; it brings Swift into the project and needs the owner's separate approval | Before the Jellyfin plugin starts, on the owner's Apple TV |
| 6 | Workers VPC stays available after its beta at a price that fits | `NODE_TRANSPORT=tunnel` without code changes; once media leaves the Worker, only control traffic depends on it | When Cloudflare announces the pricing |
| 7 | Cloudflare's terms keep the reading of 2026-10-13 | The relay's warning, the media note, and the README follow the new terms | Whenever Cloudflare updates its terms, and before 1.0 |
