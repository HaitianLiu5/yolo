# Agent Note: Yolo 1.0 和通往它的路线

Status: proposed

[English](2026-10-11-yolo-1-0.md) | 中文

## 问题

Yolo 已经能做很多事：agent（智能体）能部署和升级一个实例（[agent 部署](../../implemented/feature/2026-10-13-agent-deployment.zh.md)），媒体从节点走直连路径到屏幕（[媒体流离开 Worker](../../implemented/architecture/2026-10-13-media-off-the-worker.zh.md)），一个播放器在车上和任何浏览器里播放（[两个引擎](../../implemented/architecture/2026-10-12-two-playback-engines.zh.md)），agent 通过 MCP 和从屏幕上操作它（[远程 MCP 服务器](../../implemented/feature/2026-10-07-remote-mcp-server.zh.md)、[从屏幕上用 agent](../../implemented/feature/2026-10-18-agent-from-the-screen.zh.md)），条目有弹幕、AI 字幕、元数据，还有接着播下去的系列（[接下来播什么](../../implemented/feature/2026-10-23-up-next.zh.md)）。

一个人实际走的流程两头都是断的。新用户在没有 Plex 的情况下配对一块屏，看到的是空首页，也没有任何提示说该做什么。一个不属于任何系列、队列也为空的网页视频，播完停在"已播完"上，后面什么都不播。中间，第二块屏一开播，第一块屏就被停掉；有些失败停在一个没有按钮的遮罩上。

之前的 1.0 定义算的是部署、媒体路径、片源和插件 API，只覆盖车机和 web，使用模型是"一次只播一个"。它没有围绕屏幕前的人划定范围，所以工作分散到各个方向，主流程却一直没合上。默认配置也是照着 Yolo 成长的环境来的：局域网里的 Plex、进中国大陆的代理、登录了的 B 站账号、一辆 Tesla，而不是只有其中一样、或者一样都没有的新用户。

## 提案

### 1.0 是什么

1.0 就是主循环，在每个 1.0 端上、也跨端成立：打开 Yolo 就有东西看，看，看完有下一个，接着看，在这块屏上或另一块屏上。

```
 open ──▶ something to watch ──▶ watch ──▶ it ends ──▶ something next ──┐
  ▲          (home rows,           (no dead     (series, queue,          │
  │           cold start)           ends)        uploader, follows,      │
  │                                              agent)                  │
  └──────────── another screen takes over, with the same progress ◀──────┘
```

### 端

| 端 | 1.0 时 |
|---|---|
| Web 播放器 | Tesla 浏览器里的车机 profile（canvas 引擎），以及其他任何浏览器里的 web profile（`<video>` 引擎） |
| Apple TV | 原生 tvOS app（[Apple TV 客户端](2026-10-19-apple-tv-client.zh.md)） |
| iOS | 原生 iPhone 和 iPad app（[#72](https://github.com/HaitianLiu5/yolo/pull/72)），用同一套客户端协议 |

没有 Android 客户端：Android 手机在浏览器里运行 web 播放器，Android TV 能在 WebView 里运行它。三星电视 app（[电视 web 客户端](2026-10-26-tv-web-client.zh.md)）打开的是同一个 web 播放器，不是 1.0 的验收条件。agent 不是一个端：ChatGPT、Claude 和 Codex 通过 MCP 连到 Yolo，屏幕上的 Ask 把请求交给用户本人家里自己的 agent。

### 五个承诺

1. **打开就有东西看。** 首页由用户本人自己的来源组成：自己在用的视频网站上的关注、追番和稍后再看，Plex，以及家里的文件夹。什么都没连接时，首页说明怎么连接一个来源。
2. **看完有下一个。** 系列的下一集，然后是队列，然后是同一 UP 主或频道的下一个，然后是关注的更新，最后是 agent 挑的。
3. **每块屏各看各的，任意屏一键接手另一块屏。** 进度和已看状态所有屏共享。
4. **出错不留死胡同。** 每个失败都说明发生了什么，并给出下一步。
5. **点了就播，断了接着播。** 缓存和预取排在五个承诺的最后。

### 体验分层

| 层 | 用户本人有什么 | Yolo 给什么 |
|---|---|---|
| 地板 | 没连接任何来源；用户本人问 agent，屏幕播 agent 给的 | 仍然可用：一个条目播完后 agent 挑下一个，首页显示历史和 agent 播过的东西 |
| 正常，1.0 的目标 | 连接了自己的来源 | 首页有这些来源的行；用户本人自己发现、自己点，agent 是辅助 |
| 最好 | 多个来源、多块屏 | 屏幕之间一键接手，点了就播 |

只能播放 agent 发来的内容的屏幕是地板，永远不是 Yolo 的定位。冷启动和首页要把用户本人从地板推到正常这一层；"直接问 agent"是它们最后才给出的兜底选项，不是首选。

### 设计原则

- **为新用户设计，让用户有的选。** 不替用户本人装任何插件；用户自己选要用的来源和附加功能。
- **从不强迫登录。** 不登录任何网站，Yolo 也能用；登录只是让体验更好，比如更高的画质或者自己的关注。
- **每一步都能跳过**，以后可以在任何屏幕上、或者由用户本人的 agent 再打开。
- **不依赖任何一个站点。** 只用 YouTube、只用 Plex、或者只用家里一个文件夹的用户，都能到达正常这一层。主流程（首页、看完播什么、多屏）不假设任何站点存在，也不需要进中国大陆的代理。
- **播放网页链接是内置的。** yt-dlp 片源始终加载：地板依赖于能播放 agent 给的任何链接，而它就是认领任意网页链接的那个片源。代码上它仍是 `plugins/` 下的一个插件，所以 core 不出现任何站点或工具的名字。首页冷启动提案（[#116](https://github.com/HaitianLiu5/yolo/pull/116)）取代了之前把 yt-dlp 移出默认列表、在设置时再提供的计划。

### 主流程，逐个场景

"现在"一栏是 2026-10-31 读代码得出的，没在设备上验证。

| 场景 | 现在 | 1.0 时 |
|---|---|---|
| A. 第一次打开 | 配对后，没有 Plex 的新用户看到空首页，没有引导 | 首页问用户本人平时在哪里看：各个视频网站、Plex、家里的文件夹，最后是问 agent。每个选项都会启用并连接它的插件（扫码登录、填 Plex 地址、选文件夹），它的行马上出现。这个问题可以跳过，所有屏幕都记住这次跳过，首页留一个不打扰的入口供以后回来。由首页冷启动提案（`2026-10-31-home-cold-start.md`，[#116](https://github.com/HaitianLiu5/yolo/pull/116)）负责 |
| B. 每天打开 | 继续看、队列、播放列表、第一个电影库（最多 200 条）和 Plex 的剧集 | 每个已连接来源都有行：profile 插件提供的关注更新、追番的下一集和稍后再看（[#110](https://github.com/HaitianLiu5/yolo/pull/110)），每个 Plex 片库都分页显示，还有文件夹。节点离线时，首页说明离线以及哪些功能还能用，而不是让行消失 |
| C. 选一个 | Web 播放器播放前显示详情页；电视上一按就播 | 每个端在播放前都显示条目是什么（简介、剧集、从哪里续播），"继续看"仍然一按就播 |
| D. 看 | 有些失败停在没有按钮、还吞掉点击的遮罩上：字幕或音轨切换失败、canvas 选择失败、首页或剧集或续播加载失败；分享页给出一个通向死胡同的音轨菜单 | 每个失败都说明发生了什么，并给出重试、关闭，或回到能用的状态 |
| E. 看完 | 一个系列（剧集、视频的分 P、播放列表）会接着播；不属于任何系列、队列也为空的单个视频停在"已播完" | 承诺 2 的接续链，agent 也能设定下一个播什么。顺序和候选由接续链提案负责，用到 #110 给出的 profile 候选 |
| F. 换屏和家人 | 一次只有一块屏在播：一块屏开播会让之前那块屏停用，在浏览器里点一下会播到正在播的那块屏上 | 每块屏有自己的会话；点一下就在这块屏上播；任意屏都能从首页一键接手另一块屏的条目、位置和音轨字幕；标为家庭屏的屏幕不把它的观看写进用户本人的历史。由多屏提案负责 |
| G. 跟 agent 说 | agent 不知道用户本人在别处关注了什么，它播的东西播完后没有下文 | agent 读用户本人的 profile（#110），能设定下一个播什么，并且是接续链的最后一环 |

### 各端验收

2026-10-31 读代码得出，没在设备上验证。

**Web 播放器，车机和 web profile。** 上面的每个场景今天都能在 web 播放器上走通，限于它"现在"一栏。缺口：

- `showStatus()` 弹出的遮罩没有按钮：字幕或音轨切换失败、canvas 选择失败、首页加载失败时。
- 只显示第一个电影库，最多 200 条。
- 只有 agent 能给队列排序、编辑播放列表。
- 节点离线时，首页的片库行无声无息地消失。
- 车机上分享没有二维码。
- 没有偏好的字幕语言，不能标记已看，不能手动选画质。

**Apple TV。** 缺：详情页；下一集卡片和结束页；带重试的出错提示；队列和播放列表；遥控别的屏和移屏；Ask 的麦克风；agent canvas（在一个分支上做）；偏好设置；屏幕上的版本显示。

**iOS（#72）。** 缺：Ask；agent canvas；遥控别的屏；队列；分享入口；从别的 app 分享进 Yolo；失败提示；结束页。手机锁屏后视频可能暂停，需要在真机上验证。

### 三个只有单一来源的新用户

三位新用户各只有一个来源，除此之外什么都没有；每一位都要在每个 1.0 端上走完整个主循环，到达正常这一层，不需要 B 站账号，不需要进中国大陆的代理，也没有自己没选的插件：

| 用户 | 连接 | 主循环 |
|---|---|---|
| 只用 YouTube | YouTube 的 profile，通过它的登录 | 首页显示订阅频道的更新和稍后再看；点一下就播一个视频；播完后播同一频道或另一个关注的下一个；另一块屏接手 |
| 只用 Plex | 自己的 Plex 服务器地址和登录 | 每个片库都分页显示；一集播完接着播这一季；一部电影播完接着播下一个；另一块屏接手 |
| 只用家里的文件夹 | 节点所在机器上的一个文件夹，或者挂载的 NAS 共享 | 电影和剧集带海报和简介；需要 remux 的文件和需要转码的文件都能播放、拖动和续播；剧集接着播；另一块屏接手 |

### 插件体系：1.0 和 1.x

插件体系由首页冷启动提案（[#116](https://github.com/HaitianLiu5/yolo/pull/116)）负责；下面是它的划分。

1.0 时：

- 新节点只加载内置的播放网页链接。其他每个插件都由用户本人选择，通过冷启动、设置 › 插件、家里机器的终端（`npm run yolo -- plugins`）或 MCP 启用、配置和停用；agent 通过 MCP 请求启用插件时，要等用户本人用 passkey 批准。
- `@useyolo/plugin-api` 仍在仓库里、仍是实验性的；它的 manifest 带上插件目录需要的信息，比如插件注册的类型、说明、选项的结构，以及它访问的主机。
- 带控制面入口的插件在家里机器上重新部署后生效，屏幕上的 agent 可以执行这次部署。
- 用户本人的 agent 可以写本地插件；它和其他插件一样经过校验、用 passkey 批准、加载和回滚，并明确提示它以节点的权限运行。
- 腾讯体育拆成自己的插件 `source-tencent-sports`，这样内置的播放网页链接不带任何登录，也不带任何选择。
- 插件有播放、进度和结束的事件钩子，接续链会用到。
- 已有实例升级后加载的插件保持不变；这一版的 `yolo-upgrade` 块写明这一点。

1.0 之后，在 1.x：`@useyolo/plugin-api` 按 semver 发布到 npm；社区索引和按固定版本安装的 `yolo install`；节点插件自己注册 MCP 工具，只有 DNS 提供方保留控制面入口；以及隔离：每个插件在自己的进程里，声明的主机通过[出口规则](../../implemented/architecture/2026-10-13-node-egress-proxy.zh.md)强制执行，只拿到声明的环境变量，永远拿不到 `NODE_SECRET`。1.0 的设计给这些都留出余地。

### 基础，沿用之前的定义

| 方面 | 1.0 时 |
|---|---|
| 部署 | 有 Cloudflare 账号（有没有域名都行）的用户本人，让自己的 agent 用随附的 skill、`yolo doctor` 和被忽略的实例文件，从打了标签的发布部署 Yolo，以后再按 changelog 升级和回滚；用户本人只在 skill 列出的检查点出手 |
| 媒体 | Worker 承载控制；媒体走第一条可用的直连路径，先局域网直连播放，再远程直连播放；只有在都不可用时，中转才承载一块屏的媒体，除非用户本人把它关了（[媒体流离开 Worker](../../implemented/architecture/2026-10-13-media-off-the-worker.zh.md)） |
| 安全 | 阻塞问题保持修复并有回归测试，未认证的路由有限流，面向互联网的部分有记录在案的安全审查 |
| 仓库 | CI 是绿的，每个包都带这一版的版本号，没有任何被跟踪的文件带某位用户本人的值，贡献指南能把新人带到一个正在播放的浏览器 |

### 待 owner 确认的事项

之前定义里的这些项目移到 1.x，除非用户本人把它们留在 1.0：

- WebDAV 片源。
- 节点的 Docker 镜像。
- [分发给其他用户](2026-10-11-distribution-to-other-owners.zh.md)：安装包、设置向导、`yolo install`，以及整个实例的备份和恢复。
- D1 里的目录：节点离线时也能浏览，以及把一个条目对应到它在多个片源上的副本，让它们共享一份历史。
- 不经过 yt-dlp 播放 `.mp4`、`.m3u8` 和 `.mpd` 链接的直链片源；播放网页链接内置以后，yt-dlp 已经能播放这类链接。
- 把 `@useyolo/plugin-api` 发布到 npm（上面已列在 1.x）。
- 节点离线或证书续期失败时的提醒，以及安全审查阻塞问题之外的发现：实时通道上的设备冒充、配对锁定、内容安全策略、审计记录和可轮换的密钥。

### 不在 1.0 里

Android；音乐、播客和有声书；多个人的账号和共享片库（家庭屏不是账号，[分享链接](../../implemented/feature/2026-10-20-share-links.zh.md)只给朋友播一个条目）；[不依赖 Cloudflare 的自托管](../architecture/2026-10-07-self-hosting-without-cloudflare.zh.md)；兼容 Jellyfin 的协议；电视直播和 IPTV；节点内置的 SMB 或 NFS 客户端；profile 列表之外 Yolo 自己的关注和收件箱；用户本人的 agent 定时做的推荐；通知；在[出口路由](../../implemented/architecture/2026-10-13-node-egress-proxy.zh.md)上对冲读取；给不能转发端口的用户本人用的 R2 暂存。

## 曾考虑的替代方案

**保留按能力定义的 1.0。** 部署、媒体路径和插件 API 已经接近完成，而新用户仍然面对空首页，一个视频播完就停。人是按主循环来评判 Yolo 的，所以 1.0 由主循环定义，能力保留为它的基础。

**以 agent 为先的 1.0，屏幕播放 agent 发来的东西。** 这就是地板：只有 agent 能驱动的屏幕，在 agent 不可用、或者人不知道该问什么时毫无用处，首页也是空的。agent 仍然是辅助，是接续链的最后一环。

**默认加载所有官方插件。** 新用户会得到自己从不用的站点、登录提示，以及在自己机器上白白运行的代码；由用户本人来选，只有地板需要的播放网页链接始终加载。

**让 yt-dlp 保持可选**（[#116](https://github.com/HaitianLiu5/yolo/pull/116) 取代了这个计划）。没有它，agent 给的链接只有在别的片源认领时才能播，地板就塌了。它在代码上仍是插件，所以 core 仍然不出现任何工具的名字。

**原生 app 放到 1.0 之后。** 人们在客厅的电视和手里的手机上看，主流程必须在那里成立；[客户端协议](../../implemented/architecture/2026-10-19-client-protocol.zh.md)的服务端已经发布，所以 Apple TV 和 iOS 只需要客户端的工作。不做 Android，是因为 web 播放器已经能在它的浏览器和 WebView 里运行。

**给 Apple 设备用的 Jellyfin 协议插件。** [已否决](../../rejected/feature/2026-10-11-jellyfin-protocol-plugin.zh.md)：第三方播放器不接受遥控命令，也不显示 Yolo 自己的任何功能；Apple 客户端说的是 Yolo 自己的协议。

**为第三方客户端模拟 Plex 服务器。** [已否决](../../rejected/architecture/2026-10-11-emulate-a-plex-media-server.zh.md)：plex.tv 的认领机制和 Plex 的条款都不允许。

## 验收标准

1. **三个只有单一来源的用户到达正常这一层。** 上面只用 YouTube、只用 Plex、只用文件夹的三位用户，每一位都从配对开始，在 web 播放器的两个 profile、Apple TV 和 iOS 上走完整个主循环，不需要自己没选的插件、B 站账号或进中国大陆的代理。
2. **地板成立。** 没有连接任何来源的用户本人让 agent 在一块屏上播一个网页链接；播完后播放 agent 挑的；首页显示历史和 agent 播过的东西，并再次提供冷启动。
3. **每个场景在每个 1.0 端上都达到它"1.0 时"一栏**，各端验收里的缺口清单都已补上，并在设备上检查过。
4. **冷启动是可选的。** 在一块屏上跳过，所有屏幕都记住；播放不需要任何登录；以后可以在任何屏幕上、或由用户本人的 agent 连接一个来源。
5. **主流程里没有站点。** `service/` 和 `clients/` 下没有任何文件出现站点名字，`scripts/provider-names.test.js` 通过；只加载 Plex 或只加载文件夹时，没有任何请求发往视频网站。
6. **已有实例升级后不变。** 升级后它加载的插件和升级前相同，正如它的 `yolo-upgrade` 块所写。
7. **基础成立。** 朋友的 agent 从 1.0 标签的全新克隆部署，以后再升级和回滚；只要有直连路径可用，车在 LTE 上就通过远程直连播放 `hls`、`direct`、`dash_split` 和 `plex` 流；上面的安全和仓库标准成立。

## 风险
