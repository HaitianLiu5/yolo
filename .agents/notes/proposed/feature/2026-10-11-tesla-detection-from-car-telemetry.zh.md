# Agent Note: 根据车上的 env 事件设计特斯拉识别方法

Status: proposed

[English](2026-10-11-tesla-detection-from-car-telemetry.md) | 中文

## 问题

从软件 2026.26 起，特斯拉浏览器发送不带「Tesla」的桌面 Chrome user agent，所以 Yolo 只能从屏幕来猜是不是车：一个满分 14 分的指纹，阈值取自一个社区项目（[设备码配对](../../implemented/feature/2026-10-07-device-code-pairing.zh.md)）。全屏模式下宽度和宽度比都对不上，得分可能低于 9 分的阈值。这个猜测决定了确认页上默认的名称和类型，以及默认的[显示大小](../../implemented/feature/2026-10-11-display-size.zh.md)，所以猜错会在两处都体现出来。

## 提案

`env` 事件已经上报了更好的方法所需的数据（[设备埋点](../../implemented/feature/2026-10-11-device-telemetry.zh.md)）：指纹的得分明细（`tesla`），以及一个有上限的原生桥探测——去掉标准名字之后的全局名、已知桥接名（例如 `qt`、`cefQuery`、`chrome.webview`、`webkit.messageHandlers`、`tesla`、`QtCarBrowser`）的类型和键名，以及 `navigator` 上的非标准属性。读取车在普通模式和全屏模式下的 `env` 事件，然后：

- 如果某个桥接名或全局名只在车机浏览器里出现，就优先用它来识别车，屏幕得分作为后备；
- 否则，用两种模式下测得的数值重新调整得分的区间和阈值。

## 曾考虑的替代方案

**保留 user agent 检查和现在的得分规则。** 它在普通模式下能认出用户本人的车，但在全屏时可能漏掉，而且它的阈值来自别人的测量。

**不再去猜。** 用户本人在批准时本来就会选择名称和类型，但默认的显示大小依赖于认出车，而猜得准能在每次配对时省掉一次修改。

## 验收标准

用户本人的车在普通模式和全屏模式下都被认作特斯拉，普通的桌面 Chrome 则不会；`device-fingerprint.js` 和配对记录说明了识别方法及其依据的数据。

## 风险

桥接名和全局名可能随任何一次软件更新而变化，所以基于它们的方法需要得分规则作为后备。探测必须继续只读名字、类型和键，从不调用找到的东西，否则可能在车上触发原生行为。
