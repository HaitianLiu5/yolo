# Agent Note: 根据车上的 env 事件设计特斯拉识别方法

Status: proposed

[English](2026-10-11-tesla-detection-from-car-telemetry.md) | 中文

## 问题

从软件 2026.26 起，特斯拉浏览器发送不带「Tesla」的桌面 Chrome user agent，所以 Yolo 只能从屏幕来猜是不是车：一个满分 14 分的指纹，阈值取自一个社区项目（[设备码配对](../../implemented/feature/2026-10-07-device-code-pairing.zh.md)）。全屏模式下宽度和宽度比都对不上，得分可能低于 9 分的阈值。这个猜测决定了确认页上默认的名称和类型，以及默认的[显示大小](../../implemented/feature/2026-10-11-display-size.zh.md)，所以猜错会在两处都体现出来。

2026-10-12 车在普通模式下上报的 `env` 事件回答了一部分问题（[设备埋点](../../implemented/feature/2026-10-11-device-telemetry.zh.md)）：

- user agent 是 Linux 上普通的 Chrome 148，指纹得分 14 分（满分 14）。
- 屏幕为 1254×784 个 CSS 像素（可用区域 1254×784），窗口为 773×601，`visualViewport` 为 773×601、缩放 1，`devicePixelRatio` 为 1.53。
- `maxTouchPoints` 为 16，而 `(pointer: coarse)` 和 `(hover: none)` 都是 false。
- 桥接探测没有找到原生桥：仅有的非标准全局名是 Chrome 自己的 `chrome.loadTimes`、`chrome.csi`、`chrome.app` 和 `external.AddSearchProvider`。

## 提案

靠只有车机浏览器才有的桥接名或全局名来识别车，这条路已经排除：这个版本的软件一个也没有暴露。屏幕得分仍然是识别方法。再读取车在全屏模式下的 `env` 事件，然后用两种模式下测得的数值重新调整得分的区间和阈值。Linux 桌面版 Chrome 上有 16 个触点、同时是精确指针，可以作为一个候选信号来权衡，前提是普通桌面电脑不会这样上报。

## 曾考虑的替代方案

**保留 user agent 检查和现在的得分规则。** 它在普通模式下能认出用户本人的车（14 分满分），但在全屏时可能漏掉，而且它的阈值来自别人的测量。

**优先用原生桥识别车。** 探测没有找到只有车机浏览器才有的桥接名或全局名，所以没有可以用来识别的东西。

**不再去猜。** 用户本人在批准时本来就会选择名称和类型，但默认的显示大小依赖于认出车，而猜得准能在每次配对时省掉一次修改。

## 验收标准

用户本人的车在普通模式和全屏模式下都被认作特斯拉，普通的桌面 Chrome 则不会；`device-fingerprint.js` 和配对记录说明了识别方法及其依据的数据。

## 风险

屏幕测量值可能随任何一次软件更新或不同车型的屏幕而变化，所以这些区间需要车自己的上报来保持准确。探测必须继续只读名字、类型和键，从不调用找到的东西，否则可能在车上触发原生行为。
