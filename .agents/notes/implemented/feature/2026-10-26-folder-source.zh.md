# Agent Note: 节点所在机器上的文件夹作为片源

Status: implemented

[English](2026-10-26-folder-source.md) | 中文

## 问题

Yolo 原来只有 Plex 和 yt-dlp 两个片源，所以电影和剧集放在硬盘或 NAS 上、又没有 Plex 的用户无法播放它们：用户的一位朋友为了试用 Yolo 专门装了 Plex。节点根本读不了本地文件，因为 Input 一律是 http(s) URL（[媒体管线](../architecture/2026-10-11-node-media-pipeline.zh.md)），节点也没有自己的重新封装：Plex 用它自己的直接串流做重新封装（[局域网直连播放](2026-10-12-lan-direct-play.zh.md)）。这类片库里的文件大多是 Matroska，浏览器的 `<video>` 元素和车机的 canvas 引擎都不能原样播放，音频常是 AC-3 或 DTS，字幕放在视频旁边的文件里，很多是 GB18030 编码。

## 决策

`plugins/source-folder` 列出并播放节点所在机器上若干文件夹里的视频文件，节点核心新增 `local` Input，从节点自己的磁盘提供文件：原样提供，或由 ffmpeg 按需复制或转码成 HLS。它在默认插件列表里，用户指定文件夹之前什么也不做。WebDAV、D1 里的片库目录、Docker 镜像，以及同一部作品在多个片源上共用一份历史，仍留在[自有片库提案](../../proposed/feature/2026-10-11-own-library-and-nas.zh.md)里。

### 插件

文件夹由插件的 `roots` 选项给出，否则读 `FOLDER_ROOTS`，即用 `:`（Windows 上用 `;`）分隔的绝对路径，在 `.env.example` 里有说明。NAS 以挂载到节点所在机器上的共享目录的形式接入，这是自有片库提案已经定下的。各文件夹的电影合成一个片库，剧集合成另一个，因为首页显示的是一个电影片库和若干剧集片库。节点启动时插件在后台扫描各根目录，之后每隔 `rescanMinutes`（30）分钟再扫一次；列表会等第一次扫描完成。扫描跳过隐藏文件夹、NAS 自己的文件夹（`@eaDir`、`#recycle`）、花絮和预告片，以及小于 300 MB 的 sample 文件。

一个文件是电影还是剧集，由它的文件名和所在的文件夹决定，文件名用核心的发布名解析器读取，插件 API 现在以 `parseReleaseTitle` 导出它（[元数据插件](../architecture/2026-10-25-metadata-plugins.zh.md)）：它认识 `S01E02`、`1x02`、`第1季第2集`、`EP02` 和字幕组的 `- 02`。只用数字命名的文件是所在文件夹那部剧的一集；季文件夹（`Season 1`、`S01`、`第一季`、`Specials`）给出季号，并让它上一层的文件夹成为剧名；只用标签命名的文件（`movie.mkv`）取所在文件夹的名称和年份。同一根目录下剧名相同的剧集合成一部剧，按季和集排序列出，也是[接下来播放什么](2026-10-23-up-next.zh.md)用的那一串。

| Id | 指什么 |
|---|---|
| `f-<根目录键>-<根目录下路径的哈希>` | 一个文件：一部电影或一集。`<根目录键>` 是根目录自身路径哈希的 8 位十六进制 |
| `s-<根目录键>-<剧名的哈希>` | 一部剧 |

片库条目 id 最多 128 个字母、数字和 `._~-`（[`source.js`](../../../../service/core/src/source.js)），而哈希不含路径，所以 id 无法指向根目录之外。它在多次扫描和重启之间保持不变；文件改名或共享目录换了挂载位置会得到新 id，Hub 按标题和时长搜索会再次找到它（[移动过的片库条目](2026-10-21-moved-library-items.zh.md)）。上次扫描不认识的 id 会触发一次重新扫描（最多每分钟一次），所以新加的文件在下一次定时扫描之前就能播放。ffprobe 对每个文件按路径、大小和修改时间只读一次，结果保存在插件的 `cacheDir` 里；扫描后在后台进行，让列表带上时长。

条目有两条或更多音频流时，它们就是条目的音轨。字幕是视频旁边以它命名的文件（`Movie.chs.srt`），或者当它是文件夹里唯一的视频时，文件夹和其 `Subs` 文件夹里的所有字幕文件，然后是视频内部的文本字幕流；图形字幕（PGS、VobSub）不提供，因为它们得烧进画面。字幕文件按字节顺序标记解码，否则按 UTF-8，再否则按 GB18030 或 Big5 中未知字符更少的那个；语言取自文件名里的标签（`chs`、`cht`、`chs&eng`、`eng`），否则取自字幕文本。ffmpeg 把 SRT 和 ASS 转成 WebVTT；文件内部的字幕流会被读出一次存进缓存，期间回答 `{ pending }`，因为这要读完整个文件。封面是文件旁边或剧文件夹里的海报，否则是 ffmpeg 在文件十分之一处读出的一帧，保存在缓存里。

文件是 `video` 条目，即由元数据插件说出其作品的一份拷贝（[元数据插件](../architecture/2026-10-25-metadata-plugins.zh.md)）：`file()` 给出文件，于是 `metadata-local` 读取它旁边的 NFO 文件和图片；它的标题是发布名形式的识别结果，`Show S01E08` 或 `Film (2010)`，`details()` 把它连同年份和剧集所属的剧一起给出。这样的标题带上了文件夹提供的信息，节点的标题解析器能清楚地读懂它，所以数据库插件不调用模型就能确认。匹配一旦进了缓存，列表就把文件显示成它的作品：作品的标题、类型、剧和海报，以作品的剧照或海报替代文件自己的图片；还没匹配的文件按自己的标题和图片列出并排队识别。剧是插件自己的分组，类型保持为 `show`。

`prepare` 返回 `{ type: "local", path, audio }`，`audio` 是所选音轨在文件里的流序号，用文件默认音轨时为 null。插件从不决定文件怎样到达屏幕。

### `local` Input

可以读本地文件的片源实现 `roots()`，即它的 `local` Input 可以来自的文件夹。片源注册表把 Input 的路径和这些根目录的链接都解析掉，文件在根目录之外时，或者片源没有 `roots()` 时，以 `forbidden` 拒绝，所以根目录里指向外面的链接不会播放。`input.js` 只接受绝对且规范化的路径。

管线探测文件（[`local-file.js`](../../../../service/node/src/media/local-file.js)），并用设备的能力和该路径的上限询问 `playable()`：

| `playable()` 与文件 | 交付 |
|---|---|
| `direct`，用文件的第一条音轨 | 来自 `/m/{token}/f/{n}` 的 `mp4`：按字节范围从磁盘读文件 |
| `direct` 但选了别的音轨、`remux` 或 `audio`，且视频是 H.264 | 来自 `/m/{token}/r/` 的 MPEG-TS 分片 HLS，视频直接复制；AAC 复制，其他音频转码为立体声 AAC |
| `transcode`，或视频不是 H.264 | 同样的 HLS，视频按设备的 `maxHeight` 和 `limits.maxVideoKbps` 转码为 H.264 |

MPEG-TS 能把 H.264 送到 hls.js、Safari 的原生 HLS 和 canvas 引擎，所以其他编码即使设备能解码也会被转码。

### 按需生成的 HLS

[`local-stream.js`](../../../../service/node/src/media/local-stream.js) 一次给屏幕整个文件的 VOD 播放列表，于是两个引擎都能像在任何 VOD 流里一样随意跳转，ffmpeg 在屏幕请求分片时才生成它们。分片边界在任何任务运行之前由一份计划确定：复制的视频按至少相隔 6 秒的关键帧切分，关键帧从文件自己的索引（MP4 的样本表、Matroska 文件的 cues）用几次小读取得到，否则用 ffprobe 扫描所有数据包得到，并保存在磁盘上；转码的视频每 6 秒切一次，由任务强制关键帧。从第 n 个分片开始的任务跳到该分片的第一个关键帧，保留文件的时间戳（`-copyts`），并把计划中之后的边界从那里起算交给分片复用器，因此任何任务写出的分片和时间戳都相同：屏幕跳到 ffmpeg 还没生成的位置时，会得到一个新任务和一条无缝的流。所有时间戳都后移 0.2 秒，这样没有任务会写出负的时间戳；MPEG-TS 无法携带负值，ffmpeg 否则会在每个任务里按不同的量平移它们。两个引擎都把这么小的偏移当作没有。

正在运行的任务会在 6 个分片之内到达的分片，最多等 10 秒；在任务起点之前或更远的分片，就从那里启动新任务。任务最多领先屏幕 40 个分片，超出就用 `SIGSTOP` 暂停；落后超过 8 个的分片会被删除。分片复用器的列表写上一个分片之后它才算生成完毕，所以被杀掉的任务里没写完的分片永远不会被提供。会话的目录在 `.hls-cache/` 下，随会话一起删除。

## 曾考虑的替代方案

**一个随 ffmpeg 写入而增长的播放列表**，就像分离文件的转码那样。hls.js 把没有结尾的播放列表当作直播，从边缘开始播放；原生播放器显示不出时长；跳到尚未生成的位置时，只能向 Yolo 要一条新流。由固定分片组成的 VOD 播放列表让两个引擎都能像在任何 VOD 流里一样跳转。

**由 ffmpeg 的 HLS 复用器切出固定长度的分片，每个任务从自己的起点算起。** 没有关键帧信息时，复制流的切点会随每个任务的第一个数据包移动：从 0 开始的任务和从 n 开始的任务写出的第 n 个分片不同，跳转会拼接不匹配的分片，而关键帧间隔比分片还长时会留下空分片。按文件自己的关键帧切分，对 MP4 和 Matroska 只需从索引做几次小读取。

**一律转码。** 简单且精确，但播放一个屏幕能解码其视频的 4K remux 文件，要占用用户机器上一整个 CPU；直接复制几乎不花什么。

**fMP4 分片。** 它能把 HEVC 送到 Safari，但每个任务的初始化分片在重启之间必须逐字节相同，而 ffmpeg 不保证这一点；MPEG-TS 分片各自独立。

**由插件自己选择原样播放、重新封装还是转码**，像 Plex 那样。每个本地片源都要重复探测、关键帧索引和分片器，而且插件不能提供 HTTP 也不能保存分片（[媒体管线](../architecture/2026-10-11-node-media-pipeline.zh.md)）；由核心为每个给出文件的片源统一决定一次。

**节点级的允许文件夹列表。** 用户得把每个文件夹写两遍，一遍给插件，一遍给节点；片源自己的 `roots()` 只保留一份列表，节点仍然在解析链接后用它检查每个文件。

**以根目录下的路径作为 id。** 它可读，播放时也不需要索引，但片库条目 id 不能包含斜杠、空格或中文，而且 id 里的路径又多了一处要防范 `..` 的地方。

**用文件名作标题。** 解析器能读发布名，但 `Show/Season 1/08.mkv` 只说了 `08`；文件夹给出的剧名和季会丢掉，这个文件还要花一次模型调用。模型仍然能在标题之外看到文件本来的名字。

**用文件自己的类型 `movie` 或 `episode`。** 节点把条目是作品的片源当作已经知道作品：保留片源的标题和字段，只补缺，也从不为列表识别它的条目，于是文件夹的网格会一直显示从文件推出的名字和截帧。

**每个文件夹一个片库**，里面既有电影也有剧集。首页只显示电影片库和剧集片库，混合的片库永远不会出现在那里。

**监视文件夹的变化。** 在挂载的共享目录上，文件监视不可靠，在大片库上也很耗资源；每 30 分钟重新扫描一次，再加上请求未知 id 时的那次扫描，足以发现新文件。

## 后果

没有 Plex 的用户指定文件夹后，就能在每块屏幕上播放其中的电影和剧集：浏览器能播放的 MP4 原样发送，在局域网上保持文件自身的码率；Matroska 文件通过流复制播放，几乎不占 CPU，可以随意跳转。视频旁边的字幕文件在两个引擎里都能显示，GB18030 或 Big5 的也可以；NFO 文件和海报通过 `metadata-local` 进入详情。

它也放弃了一些东西：HEVC 或 VP9 文件即使屏幕能解码也会被转码；HDR 视频转码时不做色调映射，看起来发灰；不提供图形字幕；既不是 MP4 也不是 Matroska 的文件，第一次复制播放要等 ffprobe 读完整个文件，失败时改为转码；向前跳很远时要等一个新的 ffmpeg 任务，在慢速 NAS 共享上可能要几秒；新文件要到下一次扫描后才出现在列表里。`FFMPEG_PATH` 和 `FFPROBE_PATH` 指定这两个工具，核心里其他用到 ffmpeg 的地方仍然运行 `PATH` 上的那个。文件按文件夹列出，所以同一部电影在 Plex 和文件夹里各有一份历史，直到自有片库提案的目录把它们合并。

## 测试

[`local-media.test.js`](../../../../service/node/test/local-media.test.js) 检查 `local` Input、解析链接后的根目录、分片计划和 ffmpeg 的参数，并在有 ffmpeg 时用真实文件检查：MP4 和 Matroska 文件从索引读出的关键帧与 ffprobe 扫描的结果一致、按字节范围提供的 MP4、以 HLS 播放的 Matroska 文件里从中间启动的任务写出的分片与从头启动的任务写出的相同，以及 AC-3 音频被转码。[`folder.test.js`](../../../../plugins/source-folder/test/folder.test.js) 用假的 ffprobe 检查名称、id、解析器能清楚读懂的标题、扫描、字幕文件及其编码、列表、音轨和 Input；`local-media.test.js` 还通过 `metadata-local` 把文件夹里的文件列成其 NFO 说的作品，以旁边的海报作为图片。端到端测试在 `<video>` 引擎里播放一个文件夹中的 MP4 和 Matroska 剧集，画面上显示字幕文件并做一次跳转（[`web-playback.test.js`](../../../../test/e2e/web-playback.test.js)），也在车机的 canvas 引擎里播放（[`car-playback.test.js`](../../../../test/e2e/car-playback.test.js)）。
