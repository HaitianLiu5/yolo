# Agent Note: 账号为它的屏幕记一种语言

Status: implemented

[English](2026-11-06-account-language.md) | 中文

## 问题

[每块屏幕自己选语言](2026-10-26-player-language.zh.md)，没选的屏幕跟随浏览器。用户在好几块屏幕上读中文，而这些屏幕的浏览器都是英文，所以要在每块屏幕上重新找到这个设置再选一次，每块新屏幕又都从英文开始。

## 决策

账号记一种语言，每块设为自动的屏幕都显示它。屏幕自己的选择仍然优先。

- **顺序。** 屏幕的选择，然后是账号的语言，然后是浏览器的语言（[`clients/player/src/i18n.js`](../../../../clients/player/src/i18n.js)）。
- **设置。** **设置 › 你的 Yolo › 所有屏幕 › 语言**提供自动、English 和简体中文。`PUT /v1/owner/language` 把选择存进 `language_settings`，每个用户一行，和所有用户设置一样在 passkey 会话之后；选自动就删掉这一行（[`service/control/src/store/language-settings.js`](../../../../service/control/src/store/language-settings.js)）。
- **送到屏幕。** welcome 带 `language`，是一个标签或 null；改动以 `language` 消息发给每块已连接的屏幕。两者在[客户端协议](../architecture/2026-10-19-client-protocol.zh.md)里都是可选的，所以忽略它们的客户端保持自己的语言，协议号不用变。如果 Hub 读不到语言，或者比这个改动更旧，welcome 就不带这个字段，屏幕保持已知的语言，不会退回浏览器的语言。
- **屏幕怎么做。** 它把最后听到的语言存在 `localStorage`（`yolo.accountLanguage`）里，所以页面加载时、连接之前就用这个语言绘制。如果这改变了页面显示的语言，页面就重新加载，和屏幕自己做选择时一样。屏幕上有播放器，或者有播放器留在主页后面的页面，会照常继续，等之后的 welcome 或加载时再换。被同一块屏幕的另一个窗口顶替的窗口也一样，直到它把屏幕接回来：它一加载就会发 hello，停掉另一个窗口正在播的内容。用户在哪块屏幕上改的，那块屏幕不管在播什么都立刻重新加载，因为改动就是在那块屏幕上做的。存储保存不了语言的页面，绝不会为此重新加载：下一次加载只会再问一遍，没完没了。
- **对 Yolo 说什么。** 语音请求和问 agent 时带的语言，依次是屏幕的选择、账号的语言、浏览器的语言。
- **其他语言。** 服务器接受任何语言标签，所以能显示更多语言的客户端不需要改服务器。不显示这个标签的版本把它当作没选。

## 曾考虑的替代方案

**只有一种语言，屏幕不能自己选。** 这个模型最简单，用户也永远不会碰到不一致的屏幕。但两个人在不同屏幕上看，读的语言可能不同，车上也很少有用户会话来改任何东西。[屏幕自己选的理由](2026-10-26-player-language.zh.md)依然成立，变的只是默认值。

**任何已配对的屏幕都能在“这块屏幕”那一行设置账号语言。** 只有一行会更简单，车上也不用 passkey 就能设置。但设备凭证从不能碰用户设置，而且有人为面前这块屏幕选语言时，不应该改掉其他所有人的。

**任何屏幕上的第一次选择就成为账号的语言。** 新屏幕不用用户找第二个设置就能跟随。它和上一条有同样的问题，而且会以那一行没有说明的副作用改掉其他屏幕。

**第一次绘制前通过 HTTP 询问语言。** 页面永远不会显示错的语言，但它要等网络回应才能画出任何东西，而车上的连接最不适合等待。保存最后的语言可以立刻绘制，最多纠正一次。

**立刻重新加载正在播放的屏幕。** 每块屏幕马上就能一致，但在一个房间里改一下，就会打断另一个房间里正在看的内容。

## 后果

一个设置就能改变每块设为自动的屏幕：空闲的立刻变，正在播放的稍后变。有自己选择的屏幕保持不变，直到被设回自动。改动之后才配对的屏幕，用浏览器的语言显示配对码，第一次 welcome 后加载一次。Yolo 多保存一小行，[隐私政策](../../../../site/public/privacy.html)里写明了。Apple 应用在采用之前会忽略这两种消息；Worker 自己绘制的页面（例如登录页）不读这个语言。
