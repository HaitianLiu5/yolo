# Agent Note: 赛事片库：由插件添加的比赛类型

Status: implemented

[English](2026-11-06-event-libraries.md) | 中文

## 问题

NBA 比赛以前只能作为链接进入 Yolo。用户在腾讯体育上找到一场比赛，把地址交给 Yolo，此后这场比赛就是一个标题里带比分的网页视频。这带来四个问题：

- **没有东西可以浏览。** 首页说不出现在有哪些比赛，正在打的和打完的都说不出。
- **一场比赛看起来像好几场。** 比赛在某块屏上开播时，比分被写进了标题，所以三块屏上同一场比赛的卡片分别写着"106–102""97–88"之类，同一场比赛的回放每放一节又多一条历史。
- **显示的内容是错的，还会剧透。** 比赛结束一小时后卡片还写着"直播"，比分早已不是当前比分，看首页的人都能知道比赛结果。腾讯给的图片要么是频道的广告，要么是带记分牌的画面。
- **直播位置比直播流活得还久。** 历史保存了直播流里的位置，在车机上这是一个约 17.9 亿秒的时钟读数，之后同一条目下的回放会从这里续播。

用户希望比赛成为一种类型，就像电影和剧集那样，并且由插件添加。

## 决策

### 类型是什么

插件没法自带界面：tvOS 和 iOS 是原生应用，车机是往 canvas 上画。所以类型分两层。每个客户端都认识一种不绑定提供方的呈现方式，**赛事**（event）：在某个时间发生的事。插件提供片库，新增一种运动或一个网站都不用改客户端。NBA 不是类型，它是一个类型为 `event` 的片库。

| | 电影 | 剧集 | 赛事 |
|---|---|---|---|
| 首页 | 所有电影库合成一行 | 所有剧集库合成一行 | 每个片库一行，标题用片库的标题 |
| 点一下 | 播放 | 打开分集 | 立刻播放最佳版本 |
| 子项 | 无 | 分集，是连续的 | 版本，互相替代 |
| 播完 | 停止 | 下一集 | 停止：不会在全场之后接着放第一节 |
| 继续观看 | 一条 | 每部剧一条 | 每场赛事一条 |

片库声明 `type: "event"`，条目声明 `kind: "event"` 并带 `event` 字段（`service/plugin-api`），`normalizeDetails()` 也会把它保留在条目详情里：

| 字段 | 含义 |
|---|---|
| `status` | `upcoming`、`live` 或 `ended` |
| `startsAt` | ISO 日期时间 |
| `competition` | 联赛和轮次 |
| `progress` | 直播进行到哪里，比如"Q4 05:12" |
| `sides` | `[{ name, score? }]`，对阵双方，按名字里的顺序 |

屏幕用这些字段画赛事的那一行（[`events.js`](../../../../clients/player/src/events.js) 的 `eventLine()`，[`Browse.swift`](../../../../clients/apple/YoloKit/Sources/YoloKit/Browse.swift) 的 `EventInfo.line()`）：进行中是"直播 · Q4 05:12 · 112–106"，其他时候是时间和赛事名。旧客户端会忽略不认识的片库类型，把不认识的 kind 当作视频，所以这里不需要提升 `CLIENT_PROTOCOL` 或 `NODE_PROTOCOL`，也不改表结构。

### 一个名字，不剧透

赛事的标题就是它的名字（"76人 vs 活塞"），比分变化时不变；光这一点就让三块屏的卡片一致了。比分放在 `event.sides` 里，卡片只在赛事进行中显示：用户可能还要看的比赛，卡片不能说出结果。之后卡片上也不会显示；agent 能读到比分，并被告知不要主动说。

赛事的图片由插件通过 `artwork()` 生成。腾讯插件用 ffmpeg（节点本来就有）把两个队徽并排放在深色底上，结果保存在 `cacheDir` 里（[`matchup.js`](../../../../plugins/source-tencent-sports/src/matchup.js)）。它是普通 artwork URL 后面的普通图片，所以每个已经显示缩略图的地方，包括正在播放条和历史，都不用了解赛事就能显示它。

### 一场比赛，一条记录

每个版本都把比赛列为 `parents`，比赛自己也一样，所以 `show_key` 让它在继续观看里只占一条，就像一部剧的各集只占一条；删除这条会把它们全部删除。比赛首先播放的那个版本使用比赛自己的 id，所以播放比赛和选择那个版本共用一份进度。

直播流里的位置完全不保存：`saveProgress()` 和 `recordPlay()` 对直播条目写 0，`transfer()` 不要求位置，所以回放从历史记录的位置开始。会话的"直播"只在会话使用中才显示，因为离开一段时间的直播可能已经结束了。

### 通过另一个片源播放

插件负责说明有哪些比赛；怎么播放比赛页面是另一个片源的事。新的 `delegate(source)` 方法把条目交出去：它返回 `{ url, title?, thumbnail?, artwork?, parents? }`，由第一个认领 `url` 的其他片源来 prepare（[`sources.js`](../../../../service/node/src/sources.js)）。条目保留自己的 Source，所以历史、续播和音轨选择都跟着它。`tracks`、`subtitle`、`chapters`、`storyboard`、`comments` 和 `warm` 中委托方没有实现的，由它交给的片源回答，所以回放仍能提前预热，agent 仍能读到字幕。只跳一次：另一个片源自己播放。

没有可播内容的比赛由 `delegate()` 用 `resolve_failed` 说明，而不是 `not_found`；后者会让 Hub 去片库别处找这个条目，然后说它不见了。

### `source-tencent-sports`

[`plugins/source-tencent-sports`](../../../../plugins/source-tencent-sports/) 从腾讯的赛程（`matchUnion/list`）列出一个联赛的比赛，按北京日历往前一周、往后两天，一分钟后重新询问，腾讯没有回答时保留原样。它只保留 `matchType` 为 2 的条目，也就排除了演播室节目和重播的老比赛。直播的排最前，然后是最新结束的，然后是最快开始的。条目 id 是比赛（`100000-10022600173`），版本再加上回放（`~<vid>`）或直播频道（`~live-<id>`）；腾讯 id 里的 `:` 换成 `-`，因为传给 `play` 的条目 id 不能包含冒号。

它的 `columns` 选项指定联赛，默认是 NBA。播放、直播接口和登录目前留在 `source-ytdlp`，它负责播放比赛页的 `vid` 和 `channel`；把它们迁走是[首页冷启动](../../proposed/feature/2026-10-31-home-cold-start.zh.md)拆分的剩余部分。

### 各个屏幕上

- **播放器**在播放列表前为每个赛事片库建一行，保存在首页缓存里，翻页方式和其他片库行相同。卡片的版本操作和加入队列操作一样，在编辑模式或键盘焦点下显示，打开去掉季标题的分集页。
- **Apple TV** 按一下播放，长按提供 All Versions。**iPhone 和 iPad** 保留两个目标：播放按钮播放，封面打开版本。
- **Agent** 用 `search`（`type: "event"`）找比赛，用 `browse` 查看每场的版本，在 `get_item` 里读取状态。

## 考虑过的替代方案

**复用 `show`，把联赛当剧、比赛当集。** 完全不用改客户端，但"下一个"会播放下一场比赛，一季的已看计数没有意义，比赛的版本还要再多一层。它也没有状态，所以没法说比赛正在直播。

**用运动项目命名、客户端都认识的 kind。** 下一种运动又要重做一遍，还会把提供方的词汇放进核心。

**插件描述自己的界面。** 插件自定义布局可以服务于还没想到的类型，但足够通用的词汇等于在三个客户端上做一套 UI 工具包，而用途只有一个。`event` 很小，将来有需要时可以再加第二种呈现。

**把片库加到 `source-ytdlp`。** 代码更少，但内置链接播放总是开着，每个用户都会多一行 NBA。

**`prepare()` 返回 `{ delegate: url }`**，也就是首页冷启动最初的提议。它更小，但只有 `prepare` 能跟随：比赛会失去预热，每次通过代理开始回放都要多等大约 16 秒，agent 也读不到字幕和章节。

**在客户端绘制队徽。** 客户端绘制的卡片需要在三个客户端各做一套布局，而历史、正在播放条和 agent 依然没有图片。插件生成的图片能到达所有地方。

## 影响

首页有了比赛这一行，直播和已结束的都有，每场只有一个名字和一条记录，卡片不会剧透。新增联赛只需一行选项；新增网站只需一个插件，不用改客户端。

代价：

- 以前看过的比赛保留 `ytdlp:` 记录，不会并入新记录，也不会在这一行里显示为已看。
- 比赛页链接在插件开启时归 `tencent-sports:`，关闭时归 `ytdlp:`。
- 一个联赛的比赛行很长，一天可能有十五场；可以搜索球队，关注球队留待以后。
- 点击尚未开始的比赛只会显示错误面板说明情况，没有更好的处理。
- 播放器的触屏上，比赛的其他版本要长按才能看到。
- 插件读取的是非官方赛程接口，字段可能随时变化，`source-ytdlp` 读取回放列表时也一样。
