# Agent Note：Apple 客户端拖动进度时显示当前时刻的画面

Status: implemented

[English](2026-11-07-scrub-previews.md) | 中文

## 问题

在 iPhone 和 iPad 上拖动进度条时只显示时间；在 Apple TV 上拖动时，系统进度条也没有画面，因为流很少带 AVKit 需要的 I 帧播放列表。要找一个场景，只能跳过去、等流加载、再试一次。主人想要 Infuse 那样的效果：进度条上方显示当前时刻的画面，并跟着拖动走。

## 决定

媒体节点提供会话视频任意时刻的小图，Apple 客户端在主人拖动时把它显示在进度条上方。

### 节点提供什么

流描述符的 `previews` 是 `/m/{token}/preview`；直播流和没有这项功能的节点上为 null。`GET /m/{token}/preview/{seconds}.jpg` 返回一张最宽 480 像素的 JPEG，内容接近该时刻但不要求精确。和所有 `/m/*` URL 一样，它只凭媒体令牌授权，走流的媒体路径。超过结尾的时刻返回 `400`，没有预览的流返回 `404`，节点读取已满时返回 `429`。

节点（[`frames.js`](../../../../service/node/src/media/frames.js) 的 `preview`）依次尝试下面几处，用到第一处可用的为止，读取方式和[智能体看帧](2026-10-13-video-frames.zh.md)相同：

1. **内存。** 已读过的图片，最多 64 MiB，按条目和时刻存放，所以同一条目的新流也能用上。
2. **片源自己的故事板图片**，取离该时刻最近的一格。第一张预览最多等查询 500 毫秒，更慢就改为读帧。内存里保留 8 张图。
3. **该时刻或之前最近的关键帧**（`-skip_frame nokey`），不解码其他帧：来自正在播放会话已缓存的分段、它的那一个 fMP4 HLS 分段，或在其 Input 中快速定位。播放列表的内容保留 60 秒。转码片源的会话，其分段只存在于设备播放位置附近，所以读取 `reason: "frame"` 的 `prepare()` 给出的条目；该条目在最后一次预览后保留 60 秒，然后运行它的 `stop()`。

每次读取最多 12 秒，同时最多三次；第四次会被拒绝，不排队。这些读取和智能体的帧与故事板共用的两个名额分开，也不计入每个智能体的限额，因为它们由媒体令牌授权，由客户端控制节奏。

### 客户端怎么读

[`ScrubPreviews.swift`](../../../../clients/apple/YoloKit/Sources/YoloKit/ScrubPreviews.swift) 里的 `PreviewSchedule` 决定读哪些时刻：

- 时刻落在一个网格上，间隔是视频长度的三百分之一，介于 2 到 10 秒。
- 同时最多读两张。一张读完后，接着读主人此刻所在的时刻，以及他们移动方向上的下一个时刻，所以快速拖动会跳过经过的部分。进行中的读取不会取消，因为图片之后还用得上。
- 准确的图片还没到时，显示十二个时刻以内最近的一张。
- 连续失败三次后停止读取，直到下一次拖动。`429` 只是等主人下一次移动。

[`Shared/ScrubPreviews.swift`](../../../../clients/apple/Shared/ScrubPreviews.swift) 保留该条目最近的 120 张图片，同一条目换新流时也保留。

### iPhone 和 iPad app

卡片在进度条上方跟着手指走，到两端时保持在屏幕内：图片保持视频的比例，宽度是进度条的四分之一，介于 180 到 320 点，下面是时间。拖动时中间的控件让出位置，播放在卡片后面继续。

### Apple TV app

AVKit 没有办法给它的进度条提供图片，也读不到拖动的位置，所以 `AVPlayerViewController` 关闭 `showsPlaybackControls`，只显示画面，由 [`PlayerTransport.swift`](../../../../clients/apple/TV/PlayerTransport.swift) 绘制控件并接收遥控器操作：

| Siri Remote 操作 | 播放或暂停时 | 拖动时 |
|---|---|---|
| 左右滑动 | 开始拖动并暂停画面 | 移动时刻；滑过整个触控面覆盖视频的四分之一，介于两到二十分钟 |
| 单击 | 暂停或播放，并显示控件 | 跳到该时刻，原来在播放就继续播放 |
| 播放/暂停键 | 暂停或播放，并显示控件 | 跳到该时刻并播放 |
| 按左右边缘 | 跳过十秒 | 把时刻移动十秒 |
| 下滑或按下边缘 | 焦点移到菜单 | |
| 返回键 | 依次离开菜单、隐藏控件、退出播放器 | 回到开始拖动的位置 |

播放时，控件在最后一次按键四秒后隐藏；暂停、拖动或在菜单中时保持显示。菜单就是原来进度条上的那些（字幕、音轨、弹幕、分享、移到），改为按钮，并增加一个速度菜单代替系统的。直播流显示 `LIVE`，可以在能定位的范围内拖动，但没有图片。

## 考虑过的其他方案

**给系统进度条用 I 帧播放列表。** 流的主播放列表列出 `EXT-X-I-FRAME-STREAM-INF` 时，AVKit 拖动时会显示画面。渐进式 MP4 没有可以添加它的播放列表，多数片源的 HLS 也没有，所以节点得编码单帧片段并改写主播放列表，这又多出一个 AVPlayer 可能选来播放的变体。这样能保留电视上的系统进度条，但对手机没有帮助。

**在卡片后面放第二个静音的 AVPlayer 来定位。** 它不需要服务端改动，但每个位置都要读全码率分段；把转码片源的流定位到很远的地方，还会打扰第一个播放器正在读的转码。

**对流使用 `AVAssetImageGenerator`。** 它读不了 HLS，而多数流都是 HLS。

**按窗口调用 `/v1/storyboard`。** 故事板的格子上印有时间，经过 Worker 以 base64 传输，最大 2 MiB，每次读取最多三十个时刻，还要计入为智能体设置的限额；而拖动每次只需要从媒体路径读一张小图。

**预先生成整个视频的雪碧图。** 这样能立刻响应，但为一次主人可能根本不做的拖动而预读整个视频，每个条目都要消耗片源的上游读取和节点的 CPU。

**iPhone 拖动时暂停。** 播放继续在卡片后面进行，和原来在时间后面一样，所以拖完回到原处时 Yolo 听到的没有任何变化。电视会暂停，因为那里手指抬起后拖动状态还可以保持，主人看多久，声音就会响多久。

## 后果

在每个片源上，找场景都只需一次拖动。某个时刻的第一张图要从上游读一次关键帧，在网站的 CDN 上约需一秒，片源有故事板时可以省掉这一步。节点没有升级时，流不带 `previews`，客户端只显示时间。

电视的控件现在要由 App 自己维护：焦点、遥控器按键，以及系统进度条原本免费提供的东西（比如信息面板），要么归这段代码，要么没有了。电视拖动中的暂停会作为主人的暂停上报，所以拖动结束前，其他屏幕看到的会话是暂停的。

Web 播放器仍然只显示时间；需要时可以直接使用 `previews`。
