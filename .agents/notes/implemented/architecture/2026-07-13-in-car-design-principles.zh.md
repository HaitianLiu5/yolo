# Agent Note: 车载界面的设计原则

Status: implemented

[English](2026-07-13-in-car-design-principles.md) | 中文

## 问题

播放器首先由车内乘员在大尺寸车载触摸屏上使用（它的车机模式），也在电脑或手机的浏览器里使用（它的网页模式），用户本人的网页与它并列。主要任务是尽量少打字、少精确点按，就能开始和控制媒体；控件在手机尺寸的浏览器里也要能用。没有明确的方向，每个界面都会慢慢变成开发者仪表盘，或者千篇一律的流媒体应用仿品。

## 决策

每个界面都遵循同一份设计背景：

- **气质：**沉静、直接、有电影感。它应该让人觉得可靠、专为汽车打造，而不像开发者仪表盘或千篇一律的流媒体仿品。
- **审美方向：**克制的黑色界面，对比度高，触控目标大，文字疏朗。功能状态比装饰更重要。避免霓虹效果、拥挤的卡片、细小的控件和大量模态的设置。
- **原则：**
  - 优先一次点按的选择，而不是需要输入的配置。
  - 在用户操作之前，先让当前状态可见。
  - 车内主要控件的触控目标至少 48 px（`--touch`）。
  - 播放控件在需要之前保持低调。
  - 在特斯拉和手机视口之间保持布局稳定。

调色板、间距、字号、圆角和触控尺寸都是 [`clients/player/src/style.css`](../../../../clients/player/src/style.css) 里由所有界面共用的 CSS 自定义属性：纯黑底上的中性 `oklch` 调色板、以 4 px 为单位直到 48 px 的间距、13 到 40 px 的字号，以及磨砂质感的菜单。滚动的列表不显示滚动条，后面还有内容的边缘改为渐隐并略带模糊，首页的横排和设置面板的纵向列表都是如此（由 [`scroll-edges.js`](../../../../clients/player/src/scroll-edges.js) 标记边缘）。所有控件使用 48 px 的触控目标（`--touch`）和 22 px 的图标，在车机默认显示大小下约为 60 个物理像素。设置面板是例外：设置是停车时改的，从不在开车时改，所以它用手机设置页的密度，48 px 的行里放 40 px 的触控目标，车上也一样。正在观看的人看到的错误只有一句话和 **Try again**、**Back** 两个按钮（再试一次也播不了时只有 **Back**），从不显示技术细节（[设备埋点](../feature/2026-10-11-device-telemetry.zh.md)）。所有屏幕上的等待都是同一种样子：启动时还没有内容可显示，就显示启动标志；条目尚在路上的地方显示占位色的骨架屏，在电脑或手机的浏览器里逐张卡片闪过微光，在车上保持静止（一直在动的页面永远不会空闲，车每一帧都得重画）；从点按到开始播放，显示条目自己的图片，上面是那个加载圆环；按"下一个"、"上一个"或结束页上的卡片也一样（[接下来播什么](../feature/2026-10-23-up-next.zh.md#on-the-screen)）。没有任何屏幕显示「Connecting…」或「Loading…」（[Yolo Web](../feature/2026-10-11-yolo-web-client.zh.md#starting-up)）。

车机浏览器的窗口在车机应用栏的上方结束：窗口高 601 个 CSS 像素（920 个物理像素），特斯拉的状态栏、浏览器的工具栏和应用栏占去 1200 像素高屏幕的其余部分。所以布局不为应用栏留出空带，只保留底边自己的安全区（`--safe-bottom`，即手机的 Home 指示条）。播放器把画面放在整个窗口的正中，而不是顶栏下方区域的正中，因为顶栏会随控件一起隐藏，那样观看时画面会偏下。进度条和控件贴着窗口的底边，正好落在 16:9 画面下方的空带里，顶栏则在画面上方的空带里；菜单放在两者之间。

播放器的控件照着手机和平板上的 YouTube 应用来做，因为车机的屏幕是触摸屏（[`controls.js`](../../../../clients/player/src/controls.js)）。点一下画面，出现一层控件，画面上不加蒙层，亮度不变：按钮组和画面中央的按钮各自带半透明底色，深到白色文字在白色画面上也看得清；顶栏的返回和标题共用一个和底行一样的胶囊，左边缘与底行对齐，标题长到胶囊放不下时，在胶囊里循环滚动，每一轮开头停一下，只在控件显示时滚动（减少动态效果时改为省略号）；进度条未播放的部分是 YouTube 那样的半透明白色，画面再暗也看得见；再点一下、播放中过 3 秒，或者鼠标移出播放器，它就隐藏。暂停会让它出现，不论暂停来自用户本人、agent（智能体）还是系统的媒体控件，暂停期间它一直显示；等待从不让它出现，因为卡顿不是暂停：卡顿、跳转或画质切换带来的新流、恢复以及首次加载，都让它保持原样，隐藏的仍然隐藏，显示的照常在 3 秒后隐藏。任何内容加载期间，画面中央都显示一个小的加载圆环，不论这层控件是否显示：细细的一圈，一半是柔和的白色，带一圈淡淡的深色光晕，所以在明亮的画面上也看得见，背后没有圆盘，直径 28 像素（车机上为 32 像素，照顾观看距离）；等待持续半秒后它才淡入，短暂的等待什么都不显示；控件显示时，它取代播放按钮上的图标。减少动态效果时它不旋转，圆弧缓缓变亮变暗。点按本身从不暂停；在车机的屏幕上，不论浏览器报告的是哪种指针，每次按下都按触摸处理。这层控件包括顶栏（返回和标题）、画面正中的上一个、播放/暂停和下一个（Yolo 的历史里有更早的条目时才有上一个，Hub 写明了接下来播什么时才有下一个；[Hub](2026-10-07-hub-and-realtime-channel.zh.md#previous-and-next)），以及底边的 YouTube 桌面版控件栏：进度条横贯其上，下面一行把其余所有控件放在左边，左舵车的司机够得着：一个胶囊里是播放/暂停、音量和时间，另一个里是弹幕、字幕（CC）、音轨、倍速、设置和全屏按钮，音轨只在有音轨可选时出现，倍速在直播之外都出现。倍速按钮打开一个面板：当前速度、一个从 0.5× 到引擎最快速度（网页上 5×，车机上 3×）的滑块（在网页的滑轨上，0.5× 到 2× 占一半），以及 0.5、1、1.5、2、3 几个预设；速度不是 1× 时，按钮上用速度数字替换速度表图标（[两个引擎](2026-10-12-two-playback-engines.zh.md#playback-speed)）。每个菜单都在打开它的按钮正上方展开，以按钮为中心，并保持在页边距之内。使用鼠标时（网页配置下、浏览器的指针能悬停且精确时；车机上从不如此），播放器就是 YouTube 的桌面版：没有中央一行，上一个和下一个放在第一个胶囊里播放/暂停的两侧，各自只在有条目时出现，悬停会在按钮上方显示它的名字。没有画中画按钮。双击左侧或右侧三分之一处后退或前进 10 秒，之后每多点一下再加 10 秒，带 YouTube 那样的波纹，且不显示控件；按住画面时以 2× 播放，松开后回到所选的速度，已是 2× 或更快时按住不起作用；向下滑动等于返回。弹幕留在控件下方，暂停时停在原处；字幕取 YouTube 的大小和位置：画面每 360 像素高对应 16 像素字号（至少 16），离画面底边为画面高度的 2%；底行显示时，字幕紧贴在它上方。鼠标指针随控件一起隐藏；流还在加载时，移动鼠标只显示指针。手机竖握时，和 YouTube 应用一样，顶栏和底行直接叠在画面上，只由正中一行播放和暂停；控件显示时，字幕移到画面下方的空带里。这一行放不下所有控件时（宽度不超过 640 个 CSS 像素），第二个胶囊可以横向滑动，边缘渐隐，每个按钮仍是完整的触控尺寸，不会被裁掉。使用鼠标时，点击播放或暂停，空格或 K、J 和 L、方向键、F、M，以及 Shift+. 和 Shift+,（加速和减速 0.25）的作用与 YouTube 相同。

双语字幕每种语言只占一行（[`subtitle-layout.js`](../../../../clients/player/src/subtitle-layout.js)）：各行的语言按文字区分（中文、日文、韩文或拉丁字母），同一语言的相邻几行连成一行，中文和日文的连接处不加空格，所以来源把中文断成两行时，仍然显示为英文一行、中文一行。只有一种语言的字幕保留作者的分行，因为那可能是两个人的对白，或者共用一种文字的两种语言。每一行尽量只占一排：比字幕区（画面宽度的 92%）宽的行缩小到正好放下，最小到原字号的四分之三；还放不下的，换成在这个字号下所需的最少排数，并取能填满这些排的最大字号。[`subtitles.js`](../../../../clients/player/src/subtitles.js) 只在字幕行变化、字幕区尺寸变化或字体载入时测量，从不逐帧测量，因为画布引擎在同一个线程上绘制，任何长任务都会丢帧。每一排的底色只跟着这一排的文字，和 YouTube 一样，不会横跨整个字幕区。iPhone 的系统播放器拿到的也是同样的分行。

同一套 token 也用于电脑或手机浏览器里的 [Yolo Web](../feature/2026-10-11-yolo-web-client.zh.md) 和用户本人的网页，后者另加一套跟随系统设置的浅色方案（[用户本人的网页](2026-10-12-owner-web-pages.zh.md)）；Yolo 标志和各设备类型的图标来自同一个模块。列表、面板和网页用间距、分组和字号层级来组织结构，而不是边框和分隔线；保持同一条左边缘、操作放在右侧，只说必要的那一句。设置是一个面板，其中的破坏性操作在原地确认，绝不在对话框上再叠对话框；每个可按的控件按下时都有动作反馈，面板用键盘和触屏都能操作。

## 后果

各个界面通过这些 token 共用一套视觉语言，所以新界面会继承调色板、间距和触控尺寸，而不是另起炉灶。选择原生以外的[显示大小](../feature/2026-10-11-display-size.zh.md)会缩放每个 CSS 像素，所以触控目标也随所选大小变小。
