# Agent Note: The /v1 HTTP API

Status: implemented

English | [中文](2026-10-07-v1-http-api.zh.md)

## Problem

Agents, the Tesla client, and future web and phone clients all need the same operations — play, control, queue, playlists, history, the library, devices — with the same errors and scopes. Drive-In's old routes were shaped around one player and one server, named Plex in their paths, and had no authentication. An API defined per client would drift from the MCP tools that do the same things.

## Decision

The control plane serves one JSON API under `/v1` ([`service/control/src/api/v1.js`](../../../../service/control/src/api/v1.js)). It and the MCP tools share one service layer (`service/control/src/services.js`), so a tool and its route cannot diverge. Every route requires one [OAuth scope](2026-10-07-oauth-authorization-server.md).

### Resources

```js
// Device
{
  id: "dev_…", name: "Model Y", kind: "car" | "browser" | "phone" | "tv" | "other",
  online: true, active: false, lastSeenAt: 1730000000000,
  capabilities: Capabilities,
}

// Item: a queue or playlist entry
{ id: "itm_…", source: Source, title, thumbnail, duration, addedAt }

// PlaybackState: the one playback state the Hub broadcasts
{
  status: "idle" | "loading" | "playing" | "paused" | "buffering",
  deviceId: "dev_…" | null,
  item: { source, title, thumbnail, duration, isLive } | null,
  position: 123.4, positionAt: 1730000000000,  // clients extrapolate progress from these two
  tracks: { subtitles: ["en", "zh"], audio: "a_2" | null },
  sessionId: "ses_…" | null,
}

// Track: a subtitle or audio track
{ id: "s_en" | "plex:123", kind: "subtitle" | "audio", language: "en",
  name: "English", auto: false, format: "text" | "image", default: false }
```

A `Source` belongs to a source plugin, and its stable key `sourceKey` (`<plugin>:<id>`) keys history, resume positions, and track preferences ([source plugin API](2026-10-11-source-plugin-api.md)). `Capabilities` is described in [capability negotiation](2026-10-07-capability-negotiation.md).

### Errors

Every error has one shape: `{ "error": { "code": "device_offline", "message": "…", "retryable": true } }`. The codes are `invalid_request`, `unauthorized`, `forbidden`, `not_found`, `device_offline`, `node_offline`, `resolve_failed`, `superseded`, and `rate_limited`.

### Routes

| Method | Path | Scope | Purpose |
|---|---|---|---|
| GET | `/v1/me` | read | The user, and whether the node is online |
| GET | `/v1/devices` | read | Devices |
| PATCH | `/v1/devices/:id` | manage | `{ name?, kind? }`: rename a device or change its type |
| DELETE | `/v1/devices/:id` | manage | Remove a device, revoke its credential, and close its realtime connection; a device credential cannot call this or `PATCH` |
| POST | `/v1/devices/self/events` | device credential | The device's own telemetry ([device telemetry](../feature/2026-10-11-device-telemetry.md)); answers 202 `{ accepted, rejected }` |
| GET | `/v1/playback` | read | The current `PlaybackState` |
| POST | `/v1/playback/play` | control | `{ source \| itemId \| url \| queueItemId, deviceId?, startTime?, reason?, autoplay?, sessionId?, maxVideoKbps? }`. Without `deviceId` it plays on the active device; without `startTime` it resumes ([progress and resume](../feature/2026-10-11-yolo-owns-progress-and-resume.md)). A device rebuilding its own stream passes `reason` (`recovery`, `seek`, `quality`) and the `sessionId` it replaces; if that session was already replaced, the answer is `superseded`. `maxVideoKbps` is the device's adaptive cap ([adaptive quality](../feature/2026-10-11-adaptive-quality.md)), `null` for none |
| POST | `/v1/playback/pause`, `/resume`, `/stop` | control | Pause, resume, stop |
| POST | `/v1/playback/seek` | control | `{ position }` |
| POST | `/v1/playback/next`, `/previous` | control | Next, previous |
| PUT | `/v1/playback/device` | control | `{ deviceId, play: true }`: move playback to another device at the same position |
| PUT | `/v1/playback/tracks` | control | `{ subtitles?: [id…], audio?: id }`; an empty array turns subtitles off |
| GET | `/v1/tracks?source=…` | read | A source's tracks; without `source`, the current item's |
| GET | `/v1/queue` | read | The queue |
| POST | `/v1/queue` | manage | `{ source, position: "next" \| "end" }` |
| POST | `/v1/queue/reorder` | manage | `{ ids: [...] }` |
| DELETE | `/v1/queue/:id`, `/v1/queue` | manage | Remove one item, or clear the queue |
| GET/POST | `/v1/playlists` | read / manage | List, create |
| GET/PATCH/DELETE | `/v1/playlists/:id` | read / manage | Read, update, delete |
| POST | `/v1/playlists/:id/items` | manage | `{ source }` |
| DELETE | `/v1/playlists/:id/items/:itemId` | manage | Remove one item |
| POST | `/v1/playlists/:id/reorder` | manage | Reorder |
| POST | `/v1/playlists/:id/enqueue` | manage | `{ position }`: add the whole playlist to the queue |
| POST | `/v1/playlists/import` | manage | `{ url, name?, enqueue? }`: import an external playlist |
| GET | `/v1/history` | read | History with resume positions |
| DELETE | `/v1/history` | manage | `{ sourceKey? }`; without it, clears everything |
| GET | `/v1/library` | read | Libraries from the node's source plugins that implement them; ids are `<source>:<id>` |
| GET | `/v1/library/:libraryId/items` | read | Browse, paged |
| GET | `/v1/library/items/:id/children` | read | Episodes and other children |
| GET | `/v1/library/search?q=` | read | Search |
| GET | `/v1/library/items/:id/artwork?variant=` | read | Artwork, passed through by the control plane |
| POST | `/v1/realtime/ticket` | read | A one-time ticket for `/v1/realtime` ([OAuth](2026-10-07-oauth-authorization-server.md)) |

The library routes only forward to the node, so no route names a provider such as Plex, and a future audiobook or music library needs no new route.

## Consequences

Agents, the Tesla client, and future clients see the same operations, errors, and scopes, and a route and its MCP tool cannot drift apart. Provider-neutral library routes keep the API stable as source plugins come and go. The API is pre-1.0: the control plane, the Tesla client, and the MCP tools ship together, so a breaking change updates all three in one commit.
