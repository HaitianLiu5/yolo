# Agent Note: /v1 HTTP API

Status: implemented

[English](2026-10-07-v1-http-api.md) | 中文

## 问题

agent（智能体）和播放器（车机模式和网页模式）都需要同一组操作——播放、控制、队列、播放列表、历史、片库、设备——并使用相同的错误和 scope。早先那个服务的路由是围绕一个播放器、一个服务设计的，路径里带着 Plex，而且没有认证。按客户端各自定义的 API 会和做同样事情的 MCP 工具逐渐偏离。

## 决策

控制面在 `/v1` 下提供一套 JSON API（[`service/control/src/api/v1.js`](../../../../service/control/src/api/v1.js)）。它和 MCP 工具共用一层服务（`service/control/src/services.js`），所以工具和对应的路由不会偏离。`/v1/owner` 之外的每个路由要求一个 [OAuth scope](2026-10-07-oauth-authorization-server.zh.md)；[用户本人的路由](#owner-routes)改用用户本人的 passkey 会话。

### 资源结构

```js
// Device
{
  id: "dev_…", name: "Model Y", kind: "car" | "browser" | "phone" | "tv" | "other",
  online: true, active: false,  // active: its session is in use
  profile: "owner" | "prf_…",    // the screen's default profile
  session: { sessionId, status, title, itemId, position, profile, inUse, handedTo? } | null,
  lastSeenAt: 1730000000000,
  capabilities: Capabilities,
}

// Profile: who is watching; the owner's is always first, with the id "owner"
{ id: "owner" | "prf_…", name: "Family" }

// Item: a queue or playlist entry
{ id: "itm_…", source: Source, title, thumbnail, duration, addedAt }

// PlaybackState: one screen's session, which the Hub broadcasts
{
  status: "idle" | "loading" | "playing" | "paused" | "buffering",
  deviceId: "dev_…" | null,
  item: { source, title, thumbnail, duration, isLive } | null,
  position: 123.4, positionAt: 1730000000000,  // clients extrapolate progress from these two
  tracks: { subtitles: ["en", "zh"], audio: "a_2" | null },
  sessionId: "ses_…" | null,
  walk?: { back: 2, forward: 1 },  // while previous and next walk through history: the items each way
  upNext?: { from: "sequence", title: "…", item: { source, title, thumbnail, duration } },  // what next plays: from "history", "queue", or "sequence"
  profile?: { id: "owner", name: "Owner" },  // whose session it is
  handedTo?: { deviceId: "dev_…", at: 1730000000000 },  // another screen continued it; it stays paused here
  handedFrom?: { deviceId: "dev_…" },  // the screen this session was continued from
  updatedAt?: 1730000000000,
}

// Track: a subtitle or audio track
{ id: "s_en" | "plex:123", kind: "subtitle" | "audio", language: "en",
  name: "English", auto: false, format: "text" | "image", default: false }
```

`Source` 归片源插件所有，它的稳定键 `sourceKey`（`<plugin>:<id>`）是历史、续播进度和音轨偏好的键（[片源插件 API](2026-10-11-source-plugin-api.zh.md)）。`Capabilities` 见[能力协商](2026-10-07-capability-negotiation.zh.md)。条目的 `thumbnail` 是 Yolo 上需要设备凭据的路径，或者是另一台主机上图片的 http(s) 网址，屏幕通过 `/v1/thumbnail` 加载；条目详情里的其他图片（`poster`、`backdrop`、`still` 和人物的 `photo`）也是这两种形式。MCP 给 agent 的是图片链接（[封面图片](../feature/2026-10-07-remote-mcp-server.zh.md#cover-images)）。

### 错误

所有错误都是同一种结构：`{ "error": { "code": "device_offline", "message": "…", "retryable": true } }`，客户端能据此采取行动的拒绝还会加上 `details`。错误码有 `invalid_request`、`unauthorized`、`forbidden`、`not_found`、`device_offline`、`node_offline`、`resolve_failed`、`superseded`、`screen_busy`、`device_ambiguous`、`nothing_playing`、`media_unreachable`（没有媒体路径能到达设备，而用户本人关掉了中转；消息写明每条路径和每个修复办法，`details` 为 `{ relayMode, reason, fixes: [{ action, text }] }`，其中的 action 有 `relay`、`remote` 和 `forward`，`forward` 还带 `port`、`address` 和 `gateway`）和 `rate_limited`。三种和屏幕有关的拒绝都是 409（[每屏会话](2026-10-31-screen-sessions.zh.md)）：`screen_busy` 表示播放或移动指定的屏幕上有别人的会话在用，`details` 为 `{ deviceId, name, profile, item: { title, thumbnail } }`，带 `replace: true` 可以照做；`device_ambiguous` 表示请求没有指定屏幕，默认规则找到好几块或一块都选不出，`details.screens` 列出每块可以问的屏幕 `{ id, name, profile, online, playing }`；`nothing_playing` 表示用户本人没有在用的会话时，针对在播内容的命令。

没有指定屏幕的请求按默认规则交给一块屏幕（`HubCore.resolveScreen()`）：配对屏幕用自己的凭据请求时交给它自己，否则交给用户本人唯一一个在用的会话；一个在用的都没有时，播放交给用户本人唯一一块在线的屏幕，命令以 `nothing_playing` 拒绝，队列的修改交给用户本人最后播过的屏幕。

|---|---|---|---|
| GET | `/v1/me` | read | 用户信息，以及节点是否在线 |
| GET | `/v1/devices` | read | `{ devices, profiles }`：设备列表，每台带上它会话的简况，以及档案列表 |
| GET | `/v1/profiles` | read | `{ profiles }`，用户本人的在最前 |
| PATCH | `/v1/devices/:id` | manage | `{ name?, kind?, profile? }`：改设备名称、类型或默认档案（档案的 id 或名字；没有 `Family` 档案时，传 `Family` 会建一个） |
| DELETE | `/v1/devices/:id` | manage | 移除设备，撤销它的凭据，并断开它的实时连接；设备凭据不能调用这个接口和 `PATCH` |
| DELETE | `/v1/devices/self` | 设备凭据 | 设备忘掉自己：它的记录和凭据都会删除，和用户本人移除它一样 |
| POST | `/v1/devices/self/events` | 设备凭据 | 设备上报自己的埋点（[设备埋点](../feature/2026-10-11-device-telemetry.zh.md)）；返回 202 `{ accepted, rejected }` |
| GET | `/v1/setup` | read | 首页的冷启动（[冷启动](../../proposed/feature/2026-10-31-home-cold-start.zh.md)）：`{ state, updatedAt, available, reason?, places }`，`state` 是 `new`、`done` 或 `skipped`（按用户保存），每个地方是 `{ id, title, summary, icon, group, languages, plugins, with, state }`，带着它的插件和会一起带上的插件，每个插件是 `{ name, title, summary, privacy, enabled }`；节点答不上来时 `available: false` |
| PUT | `/v1/setup` | manage | `{ state }`：引导里的 `skipped` 或 `done`，`new` 表示重新询问 |
| GET | `/v1/playback` | read | `?deviceId=`：那块屏幕的 `PlaybackState`；省略时，配对屏幕用自己的凭据读到自己的会话，其他请求读默认规则选出的会话（什么都没在播时为空状态） |
| GET | `/v1/playback/sessions` | read | `{ sessions }`：每块有条目的屏幕的会话，新的在前，每个带 `device`、`profile` 和 `inUse` |
| GET | `/v1/playback/up-next` | read | `?after=<sourceKey>&deviceId=` → `{ title, items }`：`next` 在那块屏幕上、这个条目之后会播的所有条目（不带 `after` 时是正在播放的条目之后），按播放顺序，最多 30 项：先沿这块屏幕的历史往前，再是它的队列，最后是它的那一串，每项是 `{ from, queueItemId?, item }`，`from` 为 `history`、`queue` 或 `sequence`，`title` 是那一串的名字。Hub 已经空闲之后，它仍然对刚播完的条目有效；屏幕的结束页读它（[接下来播什么](../feature/2026-10-23-up-next.zh.md#on-the-screen)） |
| POST | `/v1/playback/play` | control | `{ source \| itemId \| url \| queueItemId, deviceId?, startTime?, reason?, autoplay?, sessionId?, maxVideoKbps?, network?, replace? }`。省略 `deviceId` 时，发出请求的屏幕能播放就在它上面播，否则按默认规则；队列里的条目在它所在队列的屏幕上播。指定的屏幕上有别的档案的会话在用时，以 `screen_busy` 拒绝，除非带 `replace: true`。省略 `startTime` 时从新会话所属档案的历史续播（[进度和续播](../feature/2026-10-11-yolo-owns-progress-and-resume.zh.md)）。设备重建自己正在播的流时带上 `reason`（`recovery`、`seek`、`quality`）和被替换的 `sessionId`；那个会话已经被替换时返回 `superseded`。`maxVideoKbps` 是设备的自适应上限（[自适应码率](../feature/2026-10-11-adaptive-quality.zh.md)），`null` 表示不限，Hub 为这个流所走的媒体路径记下它；没有它时，流从这条路径记下的码率起步。`network`（`lan`、`wan`、`relay`，没有路径时为 null；其他任何值都算作没有路径）是在自己身上播放的设备此刻走的媒体路径；Hub 为这台设备保存它（[媒体流离开 Worker](2026-10-13-media-off-the-worker.zh.md)） |
| POST | `/v1/playback/warm` | control | `{ sources, network? }`：设备首页最先列出的条目（播放器知道自己的媒体路径后，发送「从另一块屏幕继续」的第一张卡片和历史记录的前几项，一共三项），每项是一个 Source，或者 `{ source, startTime }`，表示另一块屏幕的会话会在这里从 `startTime` 接着播，Hub 让节点按这台设备的能力、路径和记住的码率上限提前解析它们，点按其中一项时就能更快开始（[节点内部 API](2026-10-07-node-internal-api.zh.md)）。只有能播放的已配对设备为自己发送；它不存储任何东西，回答 `{ warming }`，不等节点解析完 |
| POST | `/v1/playback/pause`、`/resume`、`/stop` | control | `{ deviceId? }`：暂停、继续或停止那块屏幕的会话，省略时按默认规则；`stop` 结束会话 |
| POST | `/v1/playback/seek` | control | `{ position, deviceId? }` |
| POST | `/v1/playback/next`、`/previous` | control | `{ deviceId? }`：在历史里前进和后退，之后取队列（[Hub](2026-10-07-hub-and-realtime-channel.zh.md#previous-and-next)），在那块屏幕的会话里，省略时按默认规则；播放器自己的按钮发送它所在屏幕的 id，正在播放栏发送它控制的那块屏幕的 id |
| PUT | `/v1/playback/device` | control | `{ deviceId, from?, replace? }`：在 `deviceId` 上接着播 `from` 的会话（省略时按默认规则），带上整个上下文：条目和它此刻的位置、字幕和音轨、walk、run、排在目标屏幕原有队列前面的队列，以及档案，并标上 `handedFrom`。`from` 收到 `pause`，保持暂停并标上 `handedTo`，它在节点上的流停掉。目标屏幕的会话在用、而请求不是从目标屏幕发出时，以 `screen_busy` 拒绝，除非带 `replace: true`。返回 `{ state, device, from }` |
| PUT | `/v1/playback/tracks` | control | `{ subtitles?: [id…], audio?: id, deviceId? }`；传空数组表示关闭字幕 |
| GET | `/v1/tracks?source=…&deviceId=` | read | 某个来源的音轨；省略 `source` 时返回那块屏幕上在播内容的 |
| GET | `/v1/queue` | read | `?deviceId=`：那块屏幕的队列；每块屏幕有自己的队列，默认是发出请求的屏幕的，否则按默认规则 |
| POST | `/v1/queue` | manage | `{ source, position: "next" \| "end", count?, deviceId? }`：`count` 把它所在那一串里在它之后的条目也加进队列，合计最多 `count` 个，上限 30 |
| POST | `/v1/queue/reorder` | manage | `{ ids: [...], deviceId? }` |
| DELETE | `/v1/queue/:id`、`/v1/queue` | manage | `?deviceId=`：删除一项，或清空那块屏幕的队列 |
| GET/POST | `/v1/playlists` | read / manage | 列出、创建 |
| GET/PATCH/DELETE | `/v1/playlists/:id` | read / manage | 查看、修改、删除 |
| POST | `/v1/playlists/:id/items` | manage | `{ source }` |
| DELETE | `/v1/playlists/:id/items/:itemId` | manage | 删除一项 |
| POST | `/v1/playlists/:id/reorder` | manage | 重新排序 |
| POST | `/v1/playlists/:id/enqueue` | manage | `{ position, deviceId? }`：把整个播放列表加入一块屏幕的队列 |
| POST | `/v1/playlists/import` | manage | `{ url, name?, enqueue? }`：导入外部播放列表 |
| GET | `/v1/history` | read | `?profile=`：一个档案（它的 id 或名字）的历史，默认是发出请求的屏幕的默认档案，带续播进度、`deviceId`（最后播放每条记录的屏幕）和 `watched`：Yolo 记下的「已看完」，再播一遍也保留；屏幕只显示它，不自己推算。一部剧只给一条，用剧的 `sourceKey`，它的 `source` 是接着看的那一集（[继续观看](../feature/2026-10-11-yolo-owns-progress-and-resume.zh.md)） |
| DELETE | `/v1/history` | manage | `{ sourceKey?, profile? }`，也可以是一部剧的，会删掉它的所有记录；省略时清空那个档案的全部历史 |
| GET | `/v1/library` | read | 节点上实现了片库的片源插件提供的片库；id 为 `<片源>:<id>` |
| GET | `/v1/library/:libraryId/items` | read | 浏览，支持分页，每个条目带 Yolo 自己的进度 |
| GET | `/v1/library/items/:id` | read | 条目的详情，和 MCP `get_item` 返回的对象相同：片源的详情与元数据插件为它匹配到的作品合并后的结果、它的音轨和用户的进度（[元数据插件](2026-10-25-metadata-plugins.zh.md)）；`:id` 是任意 source key，网络视频的也可以 |
| GET | `/v1/library/items/:id/sequence` | read | 条目所在的那一串，从它开始（一部剧的各集、一个视频的分 P），供播放器的列表使用（[接下来播放](../feature/2026-10-23-up-next.zh.md)） |
| GET | `/v1/library/items/:id/children` | read | 剧集等子项，带 Yolo 自己的进度 |
| GET | `/v1/library/search?q=` | read | 搜索，带 Yolo 自己的进度 |
| GET | `/v1/library/items/:id/artwork?variant=` | read | 封面图，由控制面透传；变体 `m-<plugin>-<ref>` 是元数据插件提供的条目图片，比如文件旁边的海报 |
| GET | `/v1/frame?source=&time=&width=` | read | 视频的一张 JPEG（[视频画面](../feature/2026-10-13-video-frames.zh.md)）：`source` 是条目 id、网址或 JSON 形式的 Source，默认是正在播放的条目；`time` 是秒数或 `hh:mm:ss`，默认是正在播放条目的当前位置。响应头 `x-yolo-frame-time`、`x-yolo-frame-title`（URI 编码）、`x-yolo-frame-source` 和 `x-yolo-frame-input` 描述这一帧 |
| GET | `/v1/storyboard?source=&from=&to=&count=&width=` | read | 把条目中 `count` 个均匀分布、标好时间的画面排成网格的一张 JPEG，默认取正在播放的条目（[故事板](../feature/2026-10-13-video-frames.zh.md#storyboards)）；`x-yolo-storyboard-times` 用逗号分隔列出各小图的时间（秒），`x-yolo-storyboard-origin` 为 `storyboard` 或 `frames` |
| GET | `/v1/thumbnail?url=` | read | 别的主机上的一张图片，例如网页视频的缩略图，由节点获取（[节点内部接口](2026-10-07-node-internal-api.zh.md)），所以屏幕的每张图片都来自 Yolo 自己的源；`url` 是不超过 2048 个字符的 http(s) 网址 |
| GET | `/v1/agent` | read | `{ available, id?, title?, reason?, speech?, agents? }`：屏幕不指定时被问的那个媒体节点上的 agent 能否接受请求；屏幕可选的每个 agent 列在 `agents: [{ id, title, available, reason? }]`；节点能把录音转成文字时带 `speech: true`（[屏幕直接问用户自己的 agent](../feature/2026-10-18-agent-from-the-screen.zh.md)） |
| POST | `/v1/agent/transcriptions?language=` | control | 请求体是一段录音（`audio/wav`，16 kHz 单声道 16 位，最长 30 秒、1,000,000 字节）→ `{ text, language }`，节点转录器听出的文字；什么都不保存（[语音输入](../feature/2026-10-18-agent-from-the-screen.zh.md#voice-input)） |
| POST | `/v1/agent` | control | `{ text, language?, agent? }` → 节点上 agent 的 NDJSON 流；`agent` 是屏幕选的那个；用配对屏幕的凭据请求时，这块屏幕就是它默认的播放目标。节点收到的 `playing` 是发问那块屏幕上在播的内容，`others` 是其他在用的会话（[从屏幕上问 agent](../feature/2026-10-18-agent-from-the-screen.zh.md)） |
| GET | `/v1/agent/conversations?limit=` | read | `{ conversations }`：用户和 agent 的对话，最新的在前，每个是 `{ id, title, agentId, deviceId, createdAt, updatedAt }` |
| GET | `/v1/agent/conversations/:id` | read | 一个对话和它的 `messages`：`{ id, role, text, createdAt }`，回答另有 `steps` 和 `status`（结束前为 null） |
| POST | `/v1/agent/conversations/:id/messages` | control | `{ text, language?, agent? }` → 第一行 `{ type: "conversation", id, title }`，之后是和 `POST /v1/agent` 一样的 agent 流；id 用 `new` 表示开始新对话，问题和回答都会保存；不带 `agent` 时由回答过这段对话的 agent 继续回答 |
| DELETE | `/v1/agent/conversations/:id` | control | 删除一个对话和它的消息 |
| GET | `/v1/canvas` | read | 本屏幕的 agent 画布 `{ rev, objects }`，只对声明了画布的已配对屏幕自己的凭证有效；`canvas_ops` 的 rev 跳号时屏幕重新读取它（[agent 画布](../../proposed/architecture/2026-10-21-agent-canvas.zh.md)） |
| POST | `/v1/canvas/events` | control | `{ objectId, gesture, payload? }`：人在本屏幕上对一个对象做了什么（`press`、带 `{ option, after? }` 的 `pick`，或 `dismiss`）→ `{ event }`。选中的选项由 Hub 自己播放或加入队列，并把事件记入日志供 agent 读取 |
| POST | `/v1/realtime/ticket` | read | `/v1/realtime` 的一次性票据（[OAuth](2026-10-07-oauth-authorization-server.zh.md)） |
| POST | `/v1/shares` | control | `{ source? \| itemId? \| url? }` → 201 `{ id, url, title, expiresAt }`：一个分享链接，在朋友的浏览器里播放这个条目，没给条目时播放正在播放的内容，有效期 7 天（[分享链接](../feature/2026-10-20-share-links.zh.md)）；`url` 只在这一次显示。分享正在播放的内容时，名字取自 Hub 的状态，不问节点 |

片库相关的路由把请求转给节点，所以没有路由会出现 Plex 这类具体片源的名字，以后加有声书或音乐片库也不需要新路由。列表返回时叠上了发出请求的屏幕的默认档案的历史：条目的 `resumeAt` 和 `watched`，以及剧集或季的 `watchedEpisodes`，既算片源知道的，也算用户本人在 Yolo 里播过的（[进度和续播](../feature/2026-10-11-yolo-owns-progress-and-resume.zh.md)）。

分享链接的两个路由 `GET /v1/share/<token>` 和 `POST /v1/share/<token>/stream` 不需要凭据就会回答：Worker 在 OAuth provider 之前处理它们，路径里的 token 是它们唯一的授权（[分享链接](../feature/2026-10-20-share-links.zh.md)）。

### 用户本人的路由

用户本人的设置使用 `/v1/owner` 下的路由（[`service/control/src/api/owner.js`](../../../../service/control/src/api/owner.js)）。它们不是 OAuth 资源：只认用户本人的 passkey 会话 cookie（[passkey 登录](2026-10-08-passkey-owner-sign-in.zh.md)），bearer token（包括设备凭据）永远到不了这里（`401 unauthorized`）。每个请求都带请求头 `X-Yolo-Owner: 1`；没有这个请求头、`Sec-Fetch-Site` 不是 `same-origin`，或者修改数据却没有带上与 Yolo 自己相同的 `Origin` 的请求，都会得到 `403 forbidden`。响应一律 `no-store`。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/v1/owner/session` | `{ signedIn }`；唯一不需要会话也会回答的用户本人路由 |
| POST | `/v1/owner/session/sign-out` | 结束这个浏览器上的用户本人会话 |
| GET | `/v1/owner/devices` | 设备列表，与 `GET /v1/devices` 的返回相同 |
| PATCH | `/v1/owner/devices/:id` | `{ name?, kind?, profile? }`：改设备名称、类型或默认档案 |
| GET | `/v1/owner/profiles` | `{ profiles }`，和 `GET /v1/profiles` 一样 |
| POST | `/v1/owner/profiles` | `{ name }`：添加一个档案；返回 201 `{ id, name }` |
| PATCH | `/v1/owner/profiles/:id` | `{ name }`：给用户本人以外的档案改名 |
| DELETE | `/v1/owner/profiles/:id` | 删除用户本人以外的档案：它的历史和音轨选择一起删掉，它的屏幕改回用户本人的档案 |
| DELETE | `/v1/owner/devices/:id` | 移除设备，撤销它的凭据，并断开它的实时连接 |
| POST | `/v1/owner/pairing/approve` | `{ userCode, name?, kind?, profile? }`：批准一个待处理的配对码，效果和确认页相同（[设备码配对](../feature/2026-10-07-device-code-pairing.zh.md)） |
| GET | `/v1/owner/agents` | 已连接的 agent，每个 OAuth 客户端一项：`{ id, name, site, redirectHosts, scope, connections, createdAt }` |
| DELETE | `/v1/owner/agents/:id` | 撤销这个客户端持有的每一个授权，连同它的访问 token 和刷新 token |
| GET | `/v1/owner/passkeys` | passkey 列表：`{ id, name, synced, createdAt, lastUsedAt }`，从不返回公钥 |
| DELETE | `/v1/owner/passkeys/:id` | 移除一个 passkey（最后一个不能移除）；其他所有用户本人会话都会被登出 |
| GET | `/v1/owner/media` | 媒体路径（[媒体流离开 Worker](2026-10-13-media-off-the-worker.zh.md)）：`{ relay: { mode, on, note }, lan, remote, screens, streams }`，其中 `mode` 是 `auto`、`on` 或 `off`，`on` 表示中转能否承载媒体，`note` 是设置里关于中转显示的那一行说明，`lan` 是最近一次检查留下的局域网直连播放状态 `{ configured, status, zone, name, origin, address, notAfter, renewAt, checkedAt, error, retryAt }`，从不返回 ACME 账号私钥（[局域网直连播放](../feature/2026-10-12-lan-direct-play.zh.md)），`remote` 是远程直连的 `{ configured, on, status, reason, zone, name, origin, address, ipv6, mapping, notAfter, renewAt, reachedAt, checkedAt, error, retryAt }`，`screens` 是每块屏幕根据它最近一次的流得出的 `{ id, name, kind, online, path, at }`，`streams` 是 7 天内每条路径承载的流，即 `{ days, lan, wan, relay }` |
| PATCH | `/v1/owner/media` | `{ relay?, remote? }`：`relay` 设置中转的模式（`auto`、`on` 或 `off`；其他任何值都以 `invalid_request` 拒绝，包括有模式之前的页面发来的 `true` 和 `false`），无需确认；每次改动都写一行 `kind: "security"` 日志，并把媒体路径重新发给已连接的屏幕。`remote` 打开或关闭远程访问，并立即运行远程检查。返回同样的结构 |
| POST | `/v1/owner/media/check` | 立即运行局域网和远程检查；返回同样的结构 |
| GET | `/v1/owner/voice` | `{ languages }`：用户对 Yolo 说的几种语言，BCP 47 标签，排第一的在前；没选时是 `[]`（[语音输入](../feature/2026-10-18-agent-from-the-screen.zh.md#voice-input)） |
| PUT | `/v1/owner/voice` | `{ languages }`：整个替换，最多四种，重复的去掉；`[]` 表示清空；不是标签列表的一律以 `invalid_request` 拒绝 |
| GET | `/v1/owner/image-links` | `{ version, resetAt }`：agent 拿到的封面图片链接所用的密钥版本，以及上次重置的时间（[封面图片](../feature/2026-10-07-remote-mcp-server.zh.md#cover-images)） |
| POST | `/v1/owner/image-links/reset` | 换到下一个密钥版本，让 agent 拿到过的每个图片链接都失效，并写一行 `kind: "security"` 日志；返回同样的结构 |
| GET | `/v1/owner/shares` | `{ links }`：屏幕和 agent 生成的分享链接，最新的在前，每个是 `{ id, title, thumbnail, status, createdBy, createdAt, expiresAt, revokedAt, plays, lastPlayedAt }`，其中 `status` 是 `active`、`expired` 或 `revoked`；从不返回链接本身（[分享链接](../feature/2026-10-20-share-links.zh.md)） |
| POST | `/v1/owner/shares/:id/revoke` | 撤销一个链接：它的下一个请求会被拒绝，节点停掉它的流，并写一行 `kind: "security"` 日志；返回 `{ id, revokedAt, stopped }` |
| GET | `/v1/owner/plugins` | 节点的目录（[冷启动](../../proposed/feature/2026-10-31-home-cold-start.zh.md)）：`{ config, plugins, places, restart }`，每个插件带着清单里给屏幕的字段、`origin`、`builtIn`、`enabled`、`state`（`on`、`off`、`failed`、`stopping`、`restart`、`redeploy`）、`error?`，以及 `options`，机密选项只显示 `set` |
| PATCH | `/v1/owner/plugins/:name` | `{ enabled?, options? }`：立即在节点上打开或关闭插件、或修改它的选项，并写一行 `kind: "security"` 日志；内置插件没有开关 |
| PUT | `/v1/owner/places/:id` | `{ enabled?, without? }`：打开一个地方，连同它带上的插件（`without` 里的除外），或关闭它（只关它自己的插件） |
| GET | `/v1/owner/approvals` | `{ requests }`：还在等待的 agent 插件请求；用户在 `POST /auth/approvals/:id` `{ allow, response? }` 做决定，允许要带一次新的通行密钥断言，拒绝只要请求的 id |

添加 passkey 走登录用的接口（`/auth/passkey/register/*`），带着会话时不需要配对码。

## 后果

agent、播放器和以后的任何客户端看到的是同一组操作、错误和 scope，路由和对应的 MCP 工具也不会各走各的。与具体片源无关的片库路由让 API 在片源插件增减时保持稳定。这套 API 处于 1.0 之前：控制面、播放器和 MCP 工具一起发布，所以不兼容的改动会在一个提交里同时更新三者。
