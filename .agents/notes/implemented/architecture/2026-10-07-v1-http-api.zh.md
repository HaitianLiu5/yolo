# Agent Note: /v1 HTTP API

Status: implemented

[English](2026-10-07-v1-http-api.md) | 中文

## 问题

agent（智能体）和播放器（车机 profile 和 web profile）都需要同一组操作——播放、控制、队列、播放列表、历史、片库、设备——并使用相同的错误和 scope。早先那个服务的路由是围绕一个播放器、一个服务设计的，路径里带着 Plex，而且没有认证。按客户端各自定义的 API 会和做同样事情的 MCP 工具逐渐偏离。

## 决策

控制面在 `/v1` 下提供一套 JSON API（[`service/control/src/api/v1.js`](../../../../service/control/src/api/v1.js)）。它和 MCP 工具共用一层服务（`service/control/src/services.js`），所以工具和对应的路由不会偏离。`/v1/owner` 之外的每个路由要求一个 [OAuth scope](2026-10-07-oauth-authorization-server.zh.md)；[用户本人的路由](#owner-routes)改用用户本人的 passkey 会话。

### 资源结构

```js
// Device
{
  id: "dev_…", name: "Model Y", kind: "car" | "browser" | "phone" | "tv" | "other",
  online: true, active: false, lastSeenAt: 1730000000000,
  capabilities: Capabilities,
}

// Item: a queue or playlist entry
{ id: "itm_…", source: Source, title, thumbnail, duration, addedAt }

// PlaybackState: the one playback state the Hub broadcasts
{
  status: "idle" | "loading" | "playing" | "paused" | "buffering",
  deviceId: "dev_…" | null,
  item: { source, title, thumbnail, duration, isLive } | null,
  position: 123.4, positionAt: 1730000000000,  // clients extrapolate progress from these two
  tracks: { subtitles: ["en", "zh"], audio: "a_2" | null },
  sessionId: "ses_…" | null,
  walk?: { back: 2, forward: 1 },  // while previous and next walk through history: the items each way
  upNext?: { from: "sequence", title: "…", item: { source, title, thumbnail, duration } },  // what next plays: from "history", "queue", or "sequence"
}

// Track: a subtitle or audio track
{ id: "s_en" | "plex:123", kind: "subtitle" | "audio", language: "en",
  name: "English", auto: false, format: "text" | "image", default: false }
```

`Source` 归片源插件所有，它的稳定键 `sourceKey`（`<plugin>:<id>`）是历史、续播进度和音轨偏好的键（[片源插件 API](2026-10-11-source-plugin-api.zh.md)）。`Capabilities` 见[能力协商](2026-10-07-capability-negotiation.zh.md)。条目的 `thumbnail` 是 Yolo 上需要设备凭据的路径，或者是另一台主机上图片的 http(s) 网址，屏幕通过 `/v1/thumbnail` 加载；MCP 给 agent 的是图片链接（[封面图片](../feature/2026-10-07-remote-mcp-server.zh.md#cover-images)）。

### 错误

所有错误都是同一种结构：`{ "error": { "code": "device_offline", "message": "…", "retryable": true } }`，客户端能据此采取行动的拒绝还会加上 `details`。错误码有 `invalid_request`、`unauthorized`、`forbidden`、`not_found`、`device_offline`、`node_offline`、`resolve_failed`、`superseded`、`media_unreachable`（没有媒体路径能到达设备，而用户本人关掉了中转；消息写明每条路径和每个修复办法，`details` 为 `{ relayMode, reason, fixes: [{ action, text }] }`，其中的 action 有 `relay`、`remote` 和 `forward`，`forward` 还带 `port`、`address` 和 `gateway`）和 `rate_limited`。

### 路由

| 方法 | 路径 | scope | 说明 |
|---|---|---|---|
| GET | `/v1/me` | read | 用户信息，以及节点是否在线 |
| GET | `/v1/devices` | read | 设备列表 |
| PATCH | `/v1/devices/:id` | manage | `{ name?, kind? }`：改设备名称或类型 |
| DELETE | `/v1/devices/:id` | manage | 移除设备，撤销它的凭据，并断开它的实时连接；设备凭据不能调用这个接口和 `PATCH` |
| DELETE | `/v1/devices/self` | 设备凭据 | 设备忘掉自己：它的记录和凭据都会删除，和用户本人移除它一样 |
| POST | `/v1/devices/self/events` | 设备凭据 | 设备上报自己的埋点（[设备埋点](../feature/2026-10-11-device-telemetry.zh.md)）；返回 202 `{ accepted, rejected }` |
| GET | `/v1/playback` | read | 当前的 `PlaybackState` |
| GET | `/v1/playback/up-next` | read | `?after=<sourceKey>` → `{ title, items }`：`next` 在这个条目之后会播的所有条目（不带 `after` 时是正在播放的条目之后），按播放顺序，最多 30 项：先沿历史往前，再是队列，最后是那一串，每项是 `{ from, queueItemId?, item }`，`from` 为 `history`、`queue` 或 `sequence`，`title` 是那一串的名字。Hub 已经空闲之后，它仍然对刚播完的条目有效；屏幕的结束页读它（[接下来播什么](../feature/2026-10-23-up-next.zh.md#on-the-screen)） |
| POST | `/v1/playback/play` | control | `{ source \| itemId \| url \| queueItemId, deviceId?, startTime?, reason?, autoplay?, sessionId?, maxVideoKbps?, network? }`。省略 `deviceId` 时在当前设备上播放；省略 `startTime` 时续播（[进度和续播](../feature/2026-10-11-yolo-owns-progress-and-resume.zh.md)）。设备重建自己正在播的流时带上 `reason`（`recovery`、`seek`、`quality`）和被替换的 `sessionId`；那个会话已经被替换时返回 `superseded`。`maxVideoKbps` 是设备的自适应上限（[自适应码率](../feature/2026-10-11-adaptive-quality.zh.md)），`null` 表示不限，Hub 为这个流所走的媒体路径记下它；没有它时，流从这条路径记下的码率起步。`network`（`lan`、`wan`、`relay`，没有路径时为 null；其他任何值都算作没有路径）是在自己身上播放的设备此刻走的媒体路径；Hub 为这台设备保存它（[媒体流离开 Worker](2026-10-13-media-off-the-worker.zh.md)） |
| POST | `/v1/playback/warm` | control | `{ sources, network? }`：设备首页最先列出的条目（播放器知道自己的媒体路径后，发送历史记录里的前三项），Hub 让节点按这台设备的能力、路径和记住的码率上限提前解析它们，点按其中一项时就能更快开始（[节点内部 API](2026-10-07-node-internal-api.zh.md)）。只有能播放的已配对设备为自己发送；它不存储任何东西，回答 `{ warming }`，不等节点解析完 |
| POST | `/v1/playback/pause`、`/resume`、`/stop` | control | 暂停、继续、停止 |
| POST | `/v1/playback/seek` | control | `{ position }` |
| POST | `/v1/playback/next`、`/previous` | control | `{ deviceId? }`：在历史里前进和后退，之后取队列（[Hub](2026-10-07-hub-and-realtime-channel.zh.md#previous-and-next)），在当前设备或 `deviceId` 上播放；播放器自己的按钮发送它所在屏幕的 id |
| PUT | `/v1/playback/device` | control | `{ deviceId, play: true }`：把播放切到另一台设备，从同一位置接着播 |
| PUT | `/v1/playback/tracks` | control | `{ subtitles?: [id…], audio?: id }`；传空数组表示关闭字幕 |
| GET | `/v1/tracks?source=…` | read | 某个来源的音轨；省略 `source` 时返回当前播放项的 |
| GET | `/v1/queue` | read | 队列 |
| POST | `/v1/queue` | manage | `{ source, position: "next" \| "end", count? }`：`count` 把它所在那一串里在它之后的条目也加进队列，合计最多 `count` 个，上限 30 |
| POST | `/v1/queue/reorder` | manage | `{ ids: [...] }` |
| DELETE | `/v1/queue/:id`、`/v1/queue` | manage | 删除一项，或清空队列 |
| GET/POST | `/v1/playlists` | read / manage | 列出、创建 |
| GET/PATCH/DELETE | `/v1/playlists/:id` | read / manage | 查看、修改、删除 |
| POST | `/v1/playlists/:id/items` | manage | `{ source }` |
| DELETE | `/v1/playlists/:id/items/:itemId` | manage | 删除一项 |
| POST | `/v1/playlists/:id/reorder` | manage | 重新排序 |
| POST | `/v1/playlists/:id/enqueue` | manage | `{ position }`：把整个播放列表加入队列 |
| POST | `/v1/playlists/import` | manage | `{ url, name?, enqueue? }`：导入外部播放列表 |
| GET | `/v1/history` | read | 历史和续播进度，以及 `watched`：Yolo 记下的「已看完」，再播一遍也保留；屏幕只显示它，不自己推算 |
| DELETE | `/v1/history` | manage | `{ sourceKey? }`；省略时清空全部 |
| GET | `/v1/library` | read | 节点上实现了片库的片源插件提供的片库；id 为 `<片源>:<id>` |
| GET | `/v1/library/:libraryId/items` | read | 浏览，支持分页 |
| GET | `/v1/library/items/:id` | read | 一个条目的详情，供详情页使用，和 MCP 的 `get_item` 给的一样 |
| GET | `/v1/library/items/:id/sequence` | read | 条目所在的那一串，从它开始（一部剧的各集、一个视频的分 P），供播放器的列表使用（[接下来播放](../feature/2026-10-23-up-next.zh.md)） |
| GET | `/v1/library/items/:id/children` | read | 剧集等子项 |
| GET | `/v1/library/search?q=` | read | 搜索 |
| GET | `/v1/library/items/:id/artwork?variant=` | read | 封面图，由控制面透传 |
| GET | `/v1/frame?source=&time=&width=` | read | 视频的一张 JPEG（[视频画面](../feature/2026-10-13-video-frames.zh.md)）：`source` 是条目 id、网址或 JSON 形式的 Source，默认是正在播放的条目；`time` 是秒数或 `hh:mm:ss`，默认是正在播放条目的当前位置。响应头 `x-yolo-frame-time`、`x-yolo-frame-title`（URI 编码）、`x-yolo-frame-source` 和 `x-yolo-frame-input` 描述这一帧 |
| GET | `/v1/storyboard?source=&from=&to=&count=&width=` | read | 把条目中 `count` 个均匀分布、标好时间的画面排成网格的一张 JPEG，默认取正在播放的条目（[故事板](../feature/2026-10-13-video-frames.zh.md#storyboards)）；`x-yolo-storyboard-times` 用逗号分隔列出各小图的时间（秒），`x-yolo-storyboard-origin` 为 `storyboard` 或 `frames` |
| GET | `/v1/thumbnail?url=` | read | 别的主机上的一张图片，例如网页视频的缩略图，由节点获取（[节点内部接口](2026-10-07-node-internal-api.zh.md)），所以屏幕的每张图片都来自 Yolo 自己的源；`url` 是不超过 2048 个字符的 http(s) 网址 |
| GET | `/v1/agent` | read | `{ available, id?, title?, reason?, speech?, agents? }`：屏幕不指定时被问的那个媒体节点上的 agent 能否接受请求；屏幕可选的每个 agent 列在 `agents: [{ id, title, available, reason? }]`；节点能把录音转成文字时带 `speech: true`（[屏幕直接问用户自己的 agent](../feature/2026-10-18-agent-from-the-screen.zh.md)） |
| POST | `/v1/agent/transcriptions?language=` | control | 请求体是一段录音（`audio/wav`，16 kHz 单声道 16 位，最长 30 秒、1,000,000 字节）→ `{ text, language }`，节点转录器听出的文字；什么都不保存（[语音输入](../feature/2026-10-18-agent-from-the-screen.zh.md#voice-input)） |
| POST | `/v1/agent` | control | `{ text, language?, agent? }` → 节点上 agent 的 NDJSON 流；`agent` 是屏幕选的那个；用配对屏幕的凭据请求时，这块屏幕就是它默认的播放目标 |
| GET | `/v1/agent/conversations?limit=` | read | `{ conversations }`：用户和 agent 的对话，最新的在前，每个是 `{ id, title, agentId, deviceId, createdAt, updatedAt }` |
| GET | `/v1/agent/conversations/:id` | read | 一个对话和它的 `messages`：`{ id, role, text, createdAt }`，回答另有 `steps` 和 `status`（结束前为 null） |
| POST | `/v1/agent/conversations/:id/messages` | control | `{ text, language?, agent? }` → 第一行 `{ type: "conversation", id, title }`，之后是和 `POST /v1/agent` 一样的 agent 流；id 用 `new` 表示开始新对话，问题和回答都会保存；不带 `agent` 时由回答过这段对话的 agent 继续回答 |
| DELETE | `/v1/agent/conversations/:id` | control | 删除一个对话和它的消息 |
| POST | `/v1/realtime/ticket` | read | `/v1/realtime` 的一次性票据（[OAuth](2026-10-07-oauth-authorization-server.zh.md)） |
| POST | `/v1/shares` | control | `{ source? \| itemId? \| url? }` → 201 `{ id, url, title, expiresAt }`：一个分享链接，在朋友的浏览器里播放这个条目，没给条目时播放正在播放的内容，有效期 7 天（[分享链接](../feature/2026-10-20-share-links.zh.md)）；`url` 只在这一次显示。分享正在播放的内容时，名字取自 Hub 的状态，不问节点 |

片库相关的路由只是把请求转给节点，所以没有路由会出现 Plex 这类具体片源的名字，以后加有声书或音乐片库也不需要新路由。

分享链接的两个路由 `GET /v1/share/<token>` 和 `POST /v1/share/<token>/stream` 不需要凭据就会回答：Worker 在 OAuth provider 之前处理它们，路径里的 token 是它们唯一的授权（[分享链接](../feature/2026-10-20-share-links.zh.md)）。

### 用户本人的路由

用户本人的设置使用 `/v1/owner` 下的路由（[`service/control/src/api/owner.js`](../../../../service/control/src/api/owner.js)）。它们不是 OAuth 资源：只认用户本人的 passkey 会话 cookie（[passkey 登录](2026-10-08-passkey-owner-sign-in.zh.md)），bearer token（包括设备凭据）永远到不了这里（`401 unauthorized`）。每个请求都带请求头 `X-Yolo-Owner: 1`；没有这个请求头、`Sec-Fetch-Site` 不是 `same-origin`，或者修改数据却没有带上与 Yolo 自己相同的 `Origin` 的请求，都会得到 `403 forbidden`。响应一律 `no-store`。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/v1/owner/session` | `{ signedIn }`；唯一不需要会话也会回答的用户本人路由 |
| POST | `/v1/owner/session/sign-out` | 结束这个浏览器上的用户本人会话 |
| GET | `/v1/owner/devices` | 设备列表，与 `GET /v1/devices` 的返回相同 |
| PATCH | `/v1/owner/devices/:id` | `{ name?, kind? }`：改设备名称或类型 |
| DELETE | `/v1/owner/devices/:id` | 移除设备，撤销它的凭据，并断开它的实时连接 |
| POST | `/v1/owner/pairing/approve` | `{ userCode, name?, kind? }`：批准一个待处理的配对码，效果和确认页相同（[设备码配对](../feature/2026-10-07-device-code-pairing.zh.md)） |
| GET | `/v1/owner/agents` | 已连接的 agent，每个 OAuth 客户端一项：`{ id, name, site, redirectHosts, scope, connections, createdAt }` |
| DELETE | `/v1/owner/agents/:id` | 撤销这个客户端持有的每一个授权，连同它的访问 token 和刷新 token |
| GET | `/v1/owner/passkeys` | passkey 列表：`{ id, name, synced, createdAt, lastUsedAt }`，从不返回公钥 |
| DELETE | `/v1/owner/passkeys/:id` | 移除一个 passkey（最后一个不能移除）；其他所有用户本人会话都会被登出 |
| GET | `/v1/owner/media` | 媒体路径（[媒体流离开 Worker](2026-10-13-media-off-the-worker.zh.md)）：`{ relay: { mode, on, note }, lan, remote, screens, streams }`，其中 `mode` 是 `auto`、`on` 或 `off`，`on` 表示中转能否承载媒体，`note` 是设置里关于中转显示的那一行说明，`lan` 是最近一次检查留下的局域网直连播放状态 `{ configured, status, zone, name, origin, address, notAfter, renewAt, checkedAt, error, retryAt }`，从不返回 ACME 账号私钥（[局域网直连播放](../feature/2026-10-12-lan-direct-play.zh.md)），`remote` 是远程直连的 `{ configured, on, status, reason, zone, name, origin, address, ipv6, mapping, notAfter, renewAt, reachedAt, checkedAt, error, retryAt }`，`screens` 是每块屏幕根据它最近一次的流得出的 `{ id, name, kind, online, path, at }`，`streams` 是 7 天内每条路径承载的流，即 `{ days, lan, wan, relay }` |
| PATCH | `/v1/owner/media` | `{ relay?, remote? }`：`relay` 设置中转的模式（`auto`、`on` 或 `off`；其他任何值都以 `invalid_request` 拒绝，包括有模式之前的页面发来的 `true` 和 `false`），无需确认；每次改动都写一行 `kind: "security"` 日志，并把媒体路径重新发给已连接的屏幕。`remote` 打开或关闭远程访问，并立即运行远程检查。返回同样的结构 |
| POST | `/v1/owner/media/check` | 立即运行局域网和远程检查；返回同样的结构 |
| GET | `/v1/owner/image-links` | `{ version, resetAt }`：agent 拿到的封面图片链接所用的密钥版本，以及上次重置的时间（[封面图片](../feature/2026-10-07-remote-mcp-server.zh.md#cover-images)） |
| POST | `/v1/owner/image-links/reset` | 换到下一个密钥版本，让 agent 拿到过的每个图片链接都失效，并写一行 `kind: "security"` 日志；返回同样的结构 |
| GET | `/v1/owner/shares` | `{ links }`：屏幕和 agent 生成的分享链接，最新的在前，每个是 `{ id, title, thumbnail, status, createdBy, createdAt, expiresAt, revokedAt, plays, lastPlayedAt }`，其中 `status` 是 `active`、`expired` 或 `revoked`；从不返回链接本身（[分享链接](../feature/2026-10-20-share-links.zh.md)） |
| POST | `/v1/owner/shares/:id/revoke` | 撤销一个链接：它的下一个请求会被拒绝，节点停掉它的流，并写一行 `kind: "security"` 日志；返回 `{ id, revokedAt, stopped }` |

添加 passkey 走登录用的接口（`/auth/passkey/register/*`），带着会话时不需要配对码。

## 后果

agent、播放器和以后的任何客户端看到的是同一组操作、错误和 scope，路由和对应的 MCP 工具也不会各走各的。与具体片源无关的片库路由让 API 在片源插件增减时保持稳定。这套 API 处于 1.0 之前：控制面、播放器和 MCP 工具一起发布，所以不兼容的改动会在一个提交里同时更新三者。
